The story

Arjun runs a logging pipeline. Gzip compresses the log messages about twenty to one, which pays for itself immediately.

The request IDs are a different story. They are 32-character hex strings, one per line, and gzip gets almost exactly nothing — the compressed file is the same size as the original, occasionally a few bytes larger. He tries a stronger compressor. Nothing. He tries sorting the file first, in case ordering helps. Nothing.

So he does what engineers do and looks for the bug. There is no bug. The IDs are random, and random data cannot be compressed — not by gzip, not by anything, not ever.

This is worth stating carefully, because it is a theorem rather than a limitation of current tools. There is a number attached to every source of data, measured in bits per symbol, and no compressor can beat it on average. Not a better algorithm, not more CPU, not a cleverer model. Arjun's log messages have a low number because English text is predictable; his request IDs have the highest possible number because each hex digit is a fresh surprise.

And here is the part that makes this more than a compression story. That same number — the average surprise of a source — is what a language model is trained to minimise. When a model reports a perplexity of 12, it is saying: on average, my uncertainty about the next token is equivalent to a fair choice among 12 options. Compression and prediction are not analogous. They are the same quantity, written twice.

Say it simply

Surprisal measures how surprising one outcome is: $-\log_2p$ bits. A certainty carries zero bits; a one-in-a-million event carries about 20.

Entropy is the average surprisal of a source — its genuine information content, and the floor on how far it can be compressed.

Cross-entropy is what you actually pay when you encode using the wrong probabilities, and KL divergence is the excess: the price of being wrong, always non-negative and zero only when you are exactly right.

Mutual information is how much knowing one variable reduces your uncertainty about another — the general measure of dependence that correlation only approximates.

Huffman coding achieves the entropy bound to within one bit, the Kraft inequality says exactly which code lengths are possible at all, and perplexity is the entropy exponentiated so that it reads as "effective number of choices".

Say it precisely

Surprisal and entropy

The surprisal (or information content) of an outcome with probability $p$ is

$$I(x) = -\log_2 p(x) \quad\text{bits}$$

It is the unique function, up to scale, that is non-negative, zero at $p=1$, decreasing in $p$, and additive over independent events — $I(xy)=I(x)+I(y)$ — which is what forces a logarithm.

Entropy is its expectation:

$$H(X) = -\sum_x p(x)\log_2p(x) = E[I(X)]$$

with the convention $0\log0=0$. Properties:

  • $0\le H(X)\le\log_2|\mathcal{X}|$
  • $H(X)=0$ exactly when $X$ is deterministic
  • $H(X)=\log_2|\mathcal{X}|$ exactly when $X$ is uniform — maximum ignorance
  • $H$ is concave in $p$

For a binary variable, $H_b(p)=-p\log_2p-(1-p)\log_2(1-p)$, peaking at 1 bit for $p=\frac12$.

Joint, conditional, and the chain rule

$$H(X,Y)=-\sum_{x,y}p(x,y)\log_2p(x,y), \qquad H(Y\mid X)=\sum_xp(x)H(Y\mid X=x)$$

$$\boxed{H(X,Y)=H(X)+H(Y\mid X)}$$

and conditioning never increases entropy: $H(Y\mid X)\le H(Y)$, with equality exactly under independence. Note this is an inequality on average: a particular observation $X=x$ can leave you more uncertain than before, but no observation increases your expected uncertainty.

Cross-entropy and KL divergence

$$H(p,q) = -\sum_xp(x)\log_2q(x), \qquad D_{\mathrm{KL}}(p\|q)=\sum_xp(x)\log_2\frac{p(x)}{q(x)}$$

$$\boxed{H(p,q)=H(p)+D_{\mathrm{KL}}(p\|q)}$$

Gibbs' inequality: $D_{\mathrm{KL}}(p\|q)\ge0$, with equality iff $p=q$. So cross-entropy is minimised, over all $q$, by $q=p$ — which is the entire justification for training with a cross-entropy loss.

KL is not a metric: it is asymmetric and violates the triangle inequality. It is infinite when $q(x)=0$ while $p(x)>0$ — assigning zero probability to something that happens is infinitely costly, which is why smoothing exists.

Mutual information

$$I(X;Y)=H(X)-H(X\mid Y)=H(Y)-H(Y\mid X)=H(X)+H(Y)-H(X,Y)$$

Equivalently $I(X;Y)=D_{\mathrm{KL}}\big(p(x,y)\,\|\,p(x)p(y)\big)$, so $I\ge0$ with equality iff $X$ and $Y$ are independent. Unlike correlation, it detects any dependence, linear or not — M34's $Y=X^2$ example has zero correlation and positive mutual information.

Codes: Kraft, Huffman, and the source coding theorem

A prefix-free code (no codeword a prefix of another) with lengths $\ell_i$ exists if and only if

$$\sum_i 2^{-\ell_i}\le1 \qquad\text{(\textbf{Kraft's inequality})}$$

Source coding theorem (Shannon, 1948). For any uniquely decodable code, the expected length satisfies $L\ge H(X)$. And there exists a prefix code with

$$H(X)\le L^\* < H(X)+1$$

The gap is the cost of integer codeword lengths. Encoding blocks of $n$ symbols drives the overhead to $\frac1n$:

$$H(X)\le\frac{L_n}{n}<H(X)+\frac1n$$

Huffman coding builds the tree bottom-up, repeatedly merging the two least probable symbols. It is optimal among prefix codes — no prefix code has a smaller expected length — though it is not the only optimal one.

Arithmetic coding sidesteps the integer-length problem entirely: it encodes the whole message as a single number in $[0,1)$, narrowing an interval by each symbol's probability. A message of probability $P$ lands in an interval of width $P$ and needs about $\log_2\frac1P$ bits in total — so the per-symbol overhead vanishes without blocking, which is why modern compressors use it (or its cousin, range coding) rather than Huffman.

Channel capacity and perplexity

For a noisy channel, the capacity is

$$C=\max_{p(x)}I(X;Y)$$

the most information per use, maximised over input distributions. For a binary symmetric channel flipping each bit with probability $\varepsilon$:

$$C = 1-H_b(\varepsilon)$$

At $\varepsilon=0$ capacity is 1 bit; at $\varepsilon=\frac12$ it is 0 — the output is independent of the input. Shannon's noisy channel coding theorem says any rate below $C$ is achievable with arbitrarily small error, and any rate above it is not.

Perplexity is entropy exponentiated:

$$\mathrm{PP}=2^{H} \quad\text{(or } e^{H}\text{ in nats)}$$

A perplexity of $k$ means the uncertainty equals that of a uniform choice among $k$ options. A model's reported perplexity is $2^{H(p,q)}$ — the cross-entropy, not the entropy — so it is bounded below by $2^{H(p)}$ and can never reach 1 unless the text is deterministic.

A pinch of history

Claude Shannon's "A Mathematical Theory of Communication" (1948) created the field complete, and the entropy formula's resemblance to Boltzmann's was deliberate — von Neumann reportedly told Shannon to call it entropy because "nobody knows what entropy really is, so in a debate you will always have the advantage". Hartley had proposed $\log$ of the alphabet size in 1928; Shannon's contribution was weighting by probability.

Robert Fano set the optimal-code problem to his class at MIT in 1951; David Huffman, a student, solved it rather than sit the final exam, and his bottom-up construction beat the top-down Shannon-Fano method his professor had co-invented. Leon Kraft stated his inequality in a 1949 master's thesis. Arithmetic coding emerged through the 1970s from Rissanen and Pasco, and was held back for years by patents — which is why gzip, designed in 1992 to avoid them, still uses Huffman.

Why it's true

Result 1: why the logarithm is forced. Suppose information $I(p)$ depends only on probability, is continuous, and is additive for independent events: $I(pq)=I(p)+I(q)$. That is Cauchy's functional equation in disguise. Substituting $p=e^{-u},q=e^{-v}$ and $f(u)=I(e^{-u})$ gives $f(u+v)=f(u)+f(v)$, whose only continuous solutions are $f(u)=cu$. Hence $I(p)=-c\ln p$, and choosing $c$ so a fair coin costs one unit gives $\log_2$. The logarithm is not a modelling choice; it is the only function with the required additivity.

Result 2: $D_{\mathrm{KL}}\ge0$, by Jensen. $-\log$ is convex, so by Jensen's inequality (M36's jensen_gap, with the sign flipped for convexity):

$$D_{\mathrm{KL}}(p\|q)=\sum_xp(x)\log\frac{p(x)}{q(x)} = -\sum_xp(x)\log\frac{q(x)}{p(x)} \ge -\log\sum_xp(x)\frac{q(x)}{p(x)} = -\log\sum_{x:p(x)>0}q(x)\ge-\log1=0$$

Equality in Jensen requires $\frac{q}{p}$ constant, which with both summing to 1 forces $p=q$. The final step uses $\sum q\le1$ over the support of $p$. Everything in this module that says "you cannot do better" is this inequality in costume — including $L\ge H$ and $I(X;Y)\ge0$.

Result 3: Kraft's inequality. (Necessity.) A prefix code is a set of leaves in a binary tree. A codeword of length $\ell_i$ at depth $\ell_i$ excludes $2^{L_{\max}-\ell_i}$ of the $2^{L_{\max}}$ possible depth-$L_{\max}$ descendants, and prefix-freeness means these sets are disjoint. So $\sum_i2^{L_{\max}-\ell_i}\le2^{L_{\max}}$, which is Kraft.

(Sufficiency.) Given lengths satisfying Kraft, sort them increasing and assign codewords greedily, each time taking the leftmost available node at the required depth. Kraft guarantees you never run out.

Result 4: $L\ge H$. For any prefix code, write $q_i=\frac{2^{-\ell_i}}{S}$ with $S=\sum2^{-\ell_i}\le1$; the $q_i$ form a distribution. Then

$$L-H = \sum p_i\ell_i+\sum p_i\log_2p_i = \sum p_i\log_2\frac{p_i}{2^{-\ell_i}} = \sum p_i\log_2\frac{p_i}{q_i} - \log_2 S = D_{\mathrm{KL}}(p\|q)-\log_2S$$

Both terms are non-negative ($D\ge0$ by Result 2, and $-\log_2S\ge0$ since $S\le1$), so $L\ge H$. Equality needs $p_i=2^{-\ell_i}$ exactly — the probabilities must be powers of two — which is precisely why the bound is generally unachievable and the Huffman gap exists.

Result 5: the upper bound $L^\*<H+1$. Choose $\ell_i=\lceil\log_2\frac{1}{p_i}\rceil$. These satisfy Kraft, since $\sum2^{-\lceil\log_2(1/p_i)\rceil}\le\sum2^{-\log_2(1/p_i)}=\sum p_i=1$, so such a prefix code exists. Its length is

$$L=\sum p_i\left\lceil\log_2\frac{1}{p_i}\right\rceil < \sum p_i\left(\log_2\frac{1}{p_i}+1\right)=H+1$$

Huffman is optimal, so it is at least this good. The $+1$ is pure integer-rounding waste, and encoding blocks of $n$ amortises one such waste over $n$ symbols.

Oracle lab

The oracle computes each quantity two independent ways and checks they agree.

Entropy from the formula is checked against the actual expected length of a Huffman code built on the same distribution, which must land in $[H,H+1)$. The Kraft sum of those Huffman lengths must be exactly 1 for a complete tree. Mutual information is computed from the joint entropy and, separately, as a KL divergence from the product of the marginals. Huffman's optimality is checked by brute force against every prefix code over the same alphabet — not by trusting the construction.

The mutant builds the Huffman tree by merging the two most probable symbols, which still produces a valid prefix code, so only a length comparison catches it.

Experiment lab
Four predictions.


First, entropy is a hard floor. A source's entropy should bound every compressor, and random data — maximal entropy — should be incompressible by anything.


Second, blocking closes the Huffman gap. The overhead is below 1 bit per symbol; coding blocks of $n$ should cut it to $\frac1n$.


Third, arithmetic coding gets there without blocking, because it never rounds a per-symbol length to an integer.


Fourth, channel capacity is $1-H_b(\varepsilon)$, and it vanishes at $\varepsilon=\frac12$.

Where reality disagrees: the first table is Arjun's answer. The uniform source over 16 hex digits has entropy exactly 4.0 bits, which equals the raw encoding, so the best possible compression ratio is 1:1 — and the search over code-length assignments found nothing below 4.0, because nothing exists. His request IDs are not resistant to gzip; they are resistant to mathematics. The skewed source, by contrast, has entropy under 3.4 bits and compresses accordingly.


The blocking table shows where Huffman's famous "within 1 bit" waste actually goes. At $n=1$ the overhead on this very skewed binary source is large in relative terms — the source needs 0.72 bits per symbol but a prefix code cannot spend less than 1 whole bit on a symbol. By $n=8$ the overhead has collapsed. Arithmetic coding gets there in one step by refusing to assign integer lengths at all, which is the single idea that separates modern compressors from gzip.


And the capacity table ends at the place everyone finds counter-intuitive: at $\varepsilon=\frac12$ the capacity is exactly zero. A channel that flips half your bits is not a bad channel you can code around — it is not a channel. Note also that $\varepsilon=1$ would have capacity 1 again, since a channel that always flips is perfectly informative once you know it.

def test_chain_rule_and_conditioning():
    joint = {("x0", "y0"): 0.30, ("x0", "y1"): 0.10,
             ("x1", "y0"): 0.15, ("x1", "y1"): 0.45}
    mx = marginal(joint, 0)
    my = marginal(joint, 1)
    assert abs(mx["x0"] - 0.4) < 1e-12 and abs(mx["x1"] - 0.6) < 1e-12
    assert abs(my["y0"] - 0.45) < 1e-12 and abs(my["y1"] - 0.55) < 1e-12
    # the chain rule, exactly
    assert abs(joint_entropy(joint)
               - (entropy(mx) + conditional_entropy(joint))) < 1e-12
    # conditioning never increases entropy
    assert conditional_entropy(joint) < entropy(my)
    # for independent variables it changes nothing
    ind = {(a, b): mx[a] * my[b] for a in mx for b in my}
    assert abs(conditional_entropy(ind) - entropy(my)) < 1e-12
    assert abs(joint_entropy(ind) - (entropy(mx) + entropy(my))) < 1e-12
    # a deterministic relation leaves zero conditional entropy
    det = {("x0", "y0"): 0.4, ("x1", "y1"): 0.6}
    assert abs(conditional_entropy(det)) < 1e-12, "Y is determined by X"
    try:
        marginal(joint, 2)
        assert False, "an invalid index must raise ValueError"
    except ValueError:

def test_kl_is_nonnegative_asymmetric_and_minimised_at_p():
    import random
    rng = random.Random(1948)
    p = {"a": 0.5, "b": 0.3, "c": 0.2}
    # non-negativity over many random q, and strictly positive unless q == p
    for _ in range(300):
        w = [rng.random() + 1e-6 for _ in range(3)]
        t = sum(w)
        q = dict(zip("abc", [v / t for v in w]))
        d = kl_divergence(p, q)
        assert d >= -1e-12, (q, d)
        assert cross_entropy(p, q) >= cross_entropy(p, p) - 1e-12, \
            "no q codes p more cheaply than p itself"
        if max(abs(q[s] - p[s]) for s in p) > 1e-3:
            assert d > 0, (q, d)
    # asymmetry is real - but NOT for a reversed pair, which is symmetric
    q = {"a": 0.7, "b": 0.2, "c": 0.1}
    assert abs(kl_divergence(p, q) - kl_divergence(q, p)) > 1e-6
    rev = {"a": 0.2, "b": 0.3, "c": 0.5}
    assert abs(kl_divergence(p, rev) - kl_divergence(rev, p)) < 1e-12, \
        "a reversed pair is the one case where the two agree"
    # best_q really is the minimiser
    assert best_q(p) == p
    assert abs(kl_divergence(p, best_q(p))) < 1e-12


def test_perplexity_reads_as_effective_choices():

    for k in (2, 4, 8, 10):
        uni = {i: 1 / k for i in range(k)}

def test_mi_catches_what_correlation_misses():
    # X uniform on {-1, 0, 1}, Y = X^2: zero covariance, total dependence
    joint = {(-1, 1): 1 / 3, (0, 0): 1 / 3, (1, 1): 1 / 3}
    mx, my = {}, {}
    for (a, b), v in joint.items():
        mx[a] = mx.get(a, 0) + v
        my[b] = my.get(b, 0) + v
    ex = sum(a * v for a, v in mx.items())
    ey = sum(b * v for b, v in my.items())
    exy = sum(a * b * v for (a, b), v in joint.items())
    assert abs(exy - ex * ey) < 1e-12, "the covariance is exactly zero"
    assert mutual_information(joint) > 0.9, "but the mutual information is not"
    assert detects_dependence(joint) is True
    # a deterministic relation has I = H(Y) exactly
    det = {("a", 0): 0.4, ("b", 1): 0.6}
    from math import log2
    hy = -(0.4 * log2(0.4) + 0.6 * log2(0.6))
    assert abs(mutual_information(det) - hy) < 1e-12
    assert abs(normalised_mi(det) - 1.0) < 1e-12, "perfect dependence normalises to 1"

def test_blocking_closes_the_gap():
    from math import log2
    p = {"a": 0.8, "b": 0.2}
    H = source_coding_bounds(p)[0]
    prev = None
    for n in (1, 2, 4):

        assert len(blocks) == 2 ** n
        assert abs(sum(blocks.values()) - 1.0) < 1e-9
        # the block source has exactly n times the entropy
        Hn = -sum(v * log2(v) for v in blocks.values() if v > 0)

            Misconceptions
              

            • "A better algorithm could compress random data." No. The entropy of a uniform source over $2^k$ symbols is exactly $k$ bits, and no uniquely decodable code averages below it. Arjun's request IDs are incompressible as a matter of proof.
              • 

            • "Entropy measures disorder." It measures uncertainty given a model. The digits of $\pi$ look uniform and have high empirical entropy, yet are perfectly predictable if you know the source. Entropy is always relative to the distribution you are assuming.
              • 

            • "KL divergence is a distance." It is asymmetric and fails the triangle inequality. $D(p\|q)$ and $D(q\|p)$ answer different questions — the first penalises $q$ being small where $p$ is large, the second the reverse, which is exactly the difference between mode-covering and mode-seeking fits.
              • 

            • "Zero correlation means no information shared." Correlation sees only linear association. Mutual information is zero iff independent, which is a far stronger statement.
              • 

            • "Conditioning always reduces uncertainty." On average, yes: $H(Y\mid X)\le H(Y)$. For a particular observation $X=x$ it can increase — learning one fact can genuinely leave you more confused.
              • 

            • "Huffman is the best compressor." It is optimal among prefix codes assigning whole numbers of bits per symbol. Arithmetic coding beats it by escaping that restriction, which is why it is in every modern format.
              • 

            • "Perplexity below 1 means a very good model." Perplexity is at least 1 always, and is bounded below by $2^{H(p)}$, the irreducible uncertainty of the source. A perplexity near 1 means the text was nearly deterministic, not that the model was brilliant.
              • 

            • "Capacity means speed." It is bits per channel use, not per second, and it is an upper limit on reliable rates — Shannon's theorem is existence, not an algorithm.
              • 

            • "Entropy is a property of a file." It is a property of a source. A given file's compressibility depends entirely on the model you bring to it.
              • 

            Where it breaks
            Everything above assumes you know the distribution. In practice you estimate it from data, and the estimate is biased: the plug-in entropy estimator systematically under-estimates $H$, badly so when the alphabet is comparable to the sample size. The Miller-Madow and Nemenman-Shafee-Bialek corrections exist precisely for this, and ignoring the bias is the single most common error in applied information theory.
            

            Mutual information is worse still. Estimated from finite samples, $\hat I$ is biased upward — two independent variables will show apparent mutual information simply from sampling noise — so "MI > 0" is not evidence of dependence without a null distribution to compare against.
            

            The i.i.d. assumption behind the source coding theorem rarely holds. Real sources have memory, and the relevant quantity is the entropy rate $\lim\frac{H(X_1\ldots X_n)}{n}$, which is far below the per-symbol entropy for English. This is why context matters so much in practice and why an order-0 Huffman code on English is so much worse than gzip.
            

            For continuous variables, differential entropy is not a limit of discrete entropy, can be negative, and is not invariant under a change of variables. KL divergence and mutual information are well behaved in the continuous case; differential entropy alone is not, and treating it as "entropy" causes real confusion.
            

            Finally, none of this is about meaning. Shannon was explicit: the semantic content of a message is irrelevant to the engineering problem. And none of it bounds a particular string — that is Kolmogorov complexity, which is uncomputable.
            In your real work
            Cross-entropy loss is this module's main appearance in practice. Training a classifier minimises $H(p,q)$ over the model $q$, and Gibbs' inequality is the guarantee that the minimum sits at the truth. Label smoothing deliberately moves the target off a one-hot distribution, raising the entropy floor and preventing the infinite confidence that a zero probability would demand.
            

            Perplexity is how language models are reported, and knowing that it is $2^{\text{cross-entropy}}$ makes the numbers readable: dropping perplexity from 20 to 10 is one bit per token, which is exactly a halving of the effective choice set, and also exactly one bit less per token to store the text.
            

            Compression is the direct application. Knowing the entropy of your data tells you whether compression is worth the CPU before you measure — and whether your 1.02:1 ratio is a tuning failure or a theorem. Encrypted and already-compressed payloads are near-uniform, so compressing them wastes cycles and, when done before encryption, can leak length information (the CRIME and BREACH attacks).
            

            Mutual information drives feature selection, and the data processing inequality — $I(X;Z)\le I(X;Y)$ for a chain $X\to Y\to Z$ — says no amount of post-processing creates information. That is a useful thing to say out loud when someone proposes to recover a signal that a lossy stage has already discarded.
            

            And decision trees split on information gain, which is mutual information between the feature and the label, computed at every node of every tree you have ever fit.
            Flash cards
            What is surprisal, and why must it be a logarithm?
            -log2(p) bits. Additivity over independent events forces Cauchy's functional equation, whose only continuous solutions are logarithms.
            What does entropy bound?
            The expected length of any uniquely decodable code: L >= H. It is the hard floor on lossless compression of that source.
            State the relationship between cross-entropy, entropy and KL.
            H(p,q) = H(p) + D(p||q). Since D >= 0, cross-entropy is minimised over q at q = p — the justification for cross-entropy loss.
            Why is KL divergence non-negative?
            Jensen's inequality applied to the convex function -log. Equality requires p/q constant, which with both summing to 1 forces p = q.
            How does mutual information differ from correlation?
            I(X;Y) = 0 if and only if X and Y are INDEPENDENT. Correlation detects only linear association and can be zero for perfectly dependent variables.
            State Kraft's inequality and what it decides.
            A prefix code with lengths l_i exists iff sum 2^(-l_i) <= 1. It characterises exactly which sets of codeword lengths are possible.
            State the source coding theorem.
            H <= L* < H + 1 for the best prefix code. Coding blocks of n symbols reduces the overhead to 1/n.
            In what sense is Huffman optimal, and what beats it?
            It has the minimum expected length among PREFIX codes. Arithmetic coding beats it by not assigning whole numbers of bits per symbol.
            What is perplexity, and what is its floor?
            2 raised to the cross-entropy. It reads as an effective number of equally likely choices, and is bounded below by 2^H(p), the source's own entropy.
            What is the capacity of a binary symmetric channel?
            1 - H_b(e), where e is the crossover probability. It is zero at e = 0.5, where the output is independent of the input.
            What does the data processing inequality say?
            For a chain X -> Y -> Z, I(X;Z) <= I(X;Y). Post-processing can never create information.
