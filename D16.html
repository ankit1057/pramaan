The story

In the late 1940s at Los Alamos National Laboratory, Stanislaw Ulam was recovering from an illness and playing games of solitaire. He wondered what the exact probability was of winning a random hand. After filling pages with tedious combinatorial calculations, he realized a simpler approach: deal 100 hands, count how many games are won, and estimate the true probability empirically. Ulam shared the idea with John von Neumann, who immediately grasped its revolutionary significance for calculating neutron diffusion in thermonuclear physics, naming the technique the Monte Carlo method after the famous casino in Monaco.

In computer science, randomized algorithms split into two profound branches: Las Vegas algorithms (which always return the strictly correct answer, with random runtime, like Quicksort) and Monte Carlo algorithms (which run in deterministic time, but return an answer with an arbitrarily small probability of error, like Miller-Rabin primality testing). Later, as Big Data arrived in the 2000s, Flajolet, Martin, Cormode, and Muthukrishnan invented probabilistic streaming sketches: HyperLogLog to count billions of unique visitors using just 1.5 kilobytes of memory, and Count-Min Sketch to track heavy hitters across terabit network routers.

Say it simply

Deterministic algorithms take the same path every time. Randomized algorithms flip coins to dodge worst-case traps. In Quickselect, picking a random pivot avoids worst-case quadratic time, finding the median in lightning-fast linear expected time. In streaming, when billions of numbers flow past your computer without room to store them, Reservoir Sampling lets you pick a perfectly fair random sample of items without knowing how long the stream will be. Count-Min Sketch and HyperLogLog act like magic summaries, tracking frequencies and unique counts with tiny fractions of RAM.

Say it precisely

Randomized algorithms and probabilistic data structures trade strict determinism for performance:

  1. Las Vegas vs Monte Carlo: - Las Vegas: Correctness is guaranteed; runtime is a random variable (e.g. Randomized Quicksort, Quickselect). - Monte Carlo: Runtime is deterministic; outcome is correct with probability $\ge 1 - \delta$ (e.g. Miller-Rabin, MinHash).

  2. Quickselect & Quicksort Expectation: By linearity of expectation, randomized quicksort has expected comparisons: $$\mathbb{E}[C] = 2n \ln n - O(n) = O(n \log n)$$ Quickselect finds the $k$-th smallest element in $\mathbb{E}[T(n)] = O(n)$ time by recurring on only one subproblem: $T(n) = T(3n/4) + O(n)$.

  3. Reservoir Sampling: To select $k$ items uniformly at random from a stream of unknown length $n$: - Put the first $k$ items into the reservoir. - For each subsequent item $i \ge k$, generate random integer $j \in [0, i]$. If $j < k$, replace $\text{reservoir}[j] = \text{item}_i$. Each item has exact probability $k / n$ of being in the final sample.

  4. Count-Min Sketch: Maintains a 2D array of counters $C[d \times w]$ with $d$ pairwise independent hash functions: $$w = \lceil e / \epsilon \rceil, \quad d = \lceil \ln(1 / \delta) \rceil$$ For stream update $x$: $\forall j \in [0, d-1], \quad C[j][h_j(x)] \leftarrow C[j][h_j(x)] + 1$. Point query: $\hat{f}_x = \min_{j} C[j][h_j(x)]$. Guarantees $f_x \le \hat{f}_x \le f_x + \epsilon N$ with probability $\ge 1 - \delta$.

  5. MinHash: Estimates Jaccard similarity $J(A, B) = \frac{|A \cap B|}{|A \cup B|}$ using minimum hash values: $$\Pr_{h}[\min(h(A)) = \min(h(B))] = J(A, B)$$

Why it's true

Let us prove the mathematical correctness of Reservoir Sampling by mathematical induction on the stream length $n$. We wish to prove that after processing $n \ge k$ items, every item $1 \le m \le n$ resides in the reservoir with probability exactly $k / n$.

Base Case ($n = k$): The first $k$ items are unconditionally placed into the reservoir. The probability that item $m \le k$ is in the reservoir is $k / k = 1$. The base case holds.

Inductive Hypothesis: Assume that after processing $n$ items, every item has probability $k / n$ of being in the reservoir.

Inductive Step ($n+1$): When the $(n+1)$-th item arrives, it is selected with probability $k / (n+1)$ and placed in a uniformly random slot $j \in [0, k-1]$ of the reservoir. First, for the $(n+1)$-th item itself, the probability it is in the reservoir is directly $k / (n+1)$. Next, consider an earlier item $m \le n$. For item $m$ to remain in the reservoir after step $n+1$, two conditions must hold: 1. Item $m$ was in the reservoir at step $n$ (probability $k / n$ by inductive hypothesis). 2. Item $m$ was not evicted at step $n+1$. An eviction occurs if and only if item $n+1$ is chosen (probability $k / (n+1)$) AND item $m$'s specific slot is chosen to be overwritten (probability $1 / k$). Thus: $$\Pr(\text{evicted}) = \frac{k}{n+1} \times \frac{1}{k} = \frac{1}{n+1}$$ The probability that item $m$ survives is $1 - \frac{1}{n+1} = \frac{n}{n+1}$. Therefore, by independence: $$\Pr(m \in \text{reservoir at step } n+1) = \frac{k}{n} \times \frac{n}{n+1} = \frac{k}{n+1}$$ This completes the induction. Every single item in the stream of length $N$ has an identical probability $k / N$ of being retained, proving perfect uniformity.

Oracle lab

The Reservoir Sampling oracle verifies uniform selection probability across an unbounded stream of items without knowing the stream length in advance. Sampling $k=3$ items from a stream of 10 items over 10,000 independent Monte Carlo trials demonstrates that every single item from index 0 to 9 is selected with an empirical probability tightly clustering around the theoretical value of $3 / 10 = 0.30 \pm 0.02$.

          Misconceptions
            

          • "Randomized algorithms are non-deterministic and therefore unreliable in production" Las Vegas algorithms (like randomized Quicksort) produce 100% correct results deterministically, only varying run time. Monte Carlo error probabilities can be made arbitrarily small (e.g. 2^-128).
            • 

          • "Shuffling an array by swapping each index with a random index in [0, N-1] is uniform" That naive shuffle produces N^N possible execution paths, which cannot uniformly divide N! permutations, creating systematic statistical bias. Fisher-Yates swaps with [i, N-1], which yields exactly N! paths.
            • 

          • "Count-Min sketch can underestimate true frequencies" Count-Min Sketch counters only increment. Collisions can cause overestimation, but an item's count can never be underestimated.
            • 

          • "HyperLogLog stores actual elements of the stream" HyperLogLog stores only the position of the leading zero bit of hashed items across registers, estimating cardinalities up to billions using ~1.5 KB of memory without saving elements.
            • 

          Where it breaks
          Randomized algorithms fail when adversary input correlates with pseudo-random number generator (PRNG) states. In cryptographic settings, non-cryptographic PRNGs allow attackers to predict pivot choices or hash buckets, degrading Quicksort to $O(N^2)$ or flooding Count-Min Sketch buckets. In sketches, when stream cardinality dwarfs register capacity without proper parameter sizing, variance overwhelms point estimates.
          In your real work
          HyperLogLog is the core engine behind Redis PFADD/PFCOUNT and Google BigQuery's APPROX_COUNT_DISTINCT. Count-Min Sketch is implemented in Apache Kafka, hardware router ASICs for DDoS mitigation, and cache admission policies like Caffeine (TinyLFU). MinHash powers near-duplicate document detection in web search engines.
          Flash cards
          What is the difference between Las Vegas and Monte Carlo algorithms?
          Las Vegas algorithms always return the correct answer with variable runtime; Monte Carlo algorithms run in fixed time with a small probability of error.
          Why does the Fisher-Yates shuffle produce an unbiased permutation?
          It swaps each element i with an index chosen uniformly from [i, N-1], yielding exactly N! equally probable execution trees.
          What does Reservoir Sampling guarantee?
          Every item in a stream of unknown length N has an exact equal probability k / N of being included in the final sample.
          Why can Count-Min Sketch never underestimate a frequency?
          Counters are only incremented (+1), never decremented; hash collisions only add to the count, so min(counters) >= true_count.
          What is the collision probability in MinHash equal to?
          The exact Jaccard similarity of the two sets: Pr[min(h(A)) == min(h(B))] = |A ∩ B| / |A ∪ B|.
          What memory does HyperLogLog require to estimate cardinalities into billions?
          Approximately 1.5 kilobytes, achieving standard error around 1.04 / sqrt(m).
