The story

In late June 1945, Hungarian-American mathematician John von Neumann published a 101-page typewritten document titled "First Draft of a Report on the EDVAC." In this foundational paper, von Neumann crystallized the architectural blueprint of electronic computing: a central arithmetic unit (ALU), a central control unit with instruction registers and program counters, input/output mechanisms, and a unified primary memory holding both data and executable instructions. This unified memory architecture—known forever as the von Neumann model—enabled software to modify itself and treated code as data.

Four decades later in the early 1980s, Stanford professor John Hennessy and UC Berkeley professor David Patterson challenged prevailing processor dogma. For years, computer manufacturers had built increasingly complex CISC (Complex Instruction Set Computer) processors like the VAX and Intel 8086, featuring hundreds of intricate instructions with complicated addressing modes. Hennessy and Patterson proved that 80% of execution time was spent on a tiny subset of 20% of simple instructions. By radically simplifying the instruction set to fixed-width, load-store architectures—RISC (Reduced Instruction Set Computer)—processors could implement deep instruction pipelining, executing an instruction every single clock cycle. This RISC revolution laid the direct architectural foundation for modern ARM64 silicon, powering billions of mobile smartphones and Apple Silicon M-series chips.

Say it simply

A processor is a high-speed calculator that fetches instructions from memory, decodes what they mean, executes the math, and writes back the answer billions of times every second. But there is a massive physics problem: modern CPUs compute in a fraction of a nanosecond, while fetching data from main system RAM takes hundreds of clock cycles. To keep the CPU from sitting idle, chip architects place a hierarchy of tiny, blazing-fast SRAM memory caches (L1, L2, L3) directly on the silicon die, exploiting the fact that programs tend to reuse recent data (temporal locality) and access nearby memory locations (spatial locality).

Say it precisely

Computer architecture performance and memory hierarchy behavior are formalized by:

  1. The Iron Law of Processor Performance: The total execution time for a program is governed by: $$\text{CPU Time} = \text{Instruction Count} \times \text{CPI} \times T_{\text{clock}} = \frac{\text{Instructions} \times \text{CPI}}{\text{Clock Frequency}}$$ where $\text{CPI}$ (Cycles Per Instruction) measures execution efficiency across pipelined functional units.

  2. Average Memory Access Time (AMAT): For a multi-level cache hierarchy: $$\text{AMAT} = T_{L1} + M_{L1} \cdot \left( T_{L2} + M_{L2} \cdot \left( T_{L3} + M_{L3} \cdot T_{\text{DRAM}} \right) \right)$$ where $T_k$ is the hit latency of level $k$ and $M_k$ is the local miss rate ($0 \le M_k \le 1$).

  3. Set-Associative Cache Mapping: A physical memory address of $W$ bits is partitioned into three fields: $$\begin{array}{|c|c|c|} \hline \text{Tag } (W - S - B \text{ bits}) & \text{Set Index } (S \text{ bits}) & \text{Byte Offset } (B \text{ bits}) \\ \hline \end{array}$$ where $B = \log_2(\text{Line Size})$, $S = \log_2(\text{Number of Sets})$, and $\text{Ways} = E$. - Cache Line Size: 64 bytes (x86), 128 bytes (Apple Silicon). - The 4 C's of Cache Misses: Compulsory (cold start), Capacity (working set exceeds total cache size), Conflict (non-ideal hash collision within a set), Coherence (cache block invalidated by another core via MESI).

  4. Pipelining & Hazards: - Structural Hazards: Simultaneous hardware resource conflicts (e.g. unified memory port). - Data Hazards (RAW, WAR, WAW): True data dependency (Read-After-Write). Resolved via forwarding bypass networks or compiler scheduling stalls. - Control Hazards: Branch resolution delays. Mitigated via 2-bit branch predictors, branch target buffers (BTB), and speculative execution.

  5. Multicore Coherence (MESI Protocol): Every cache line occupies one of four states: $$\text{MESI} = \{\text{Modified (dirty, exclusive)}, \text{Exclusive (clean, private)}, \text{Shared (clean, replicated)}, \text{Invalid (stale)}\}$$

Why it's true

Understanding why CPU architects introduced out-of-order execution, deep pipelining, and aggressive branch prediction requires analyzing the "Memory Wall"—the exponentially widening performance chasm between processor clock speeds and DRAM memory access latency. Between 1980 and 2005, CPU frequencies grew at approximately 55% per year, while DRAM access latency improved by a sluggish 7% per year. Consequently, a memory load instruction that once cost 5 CPU cycles came to cost over 300 CPU cycles.

If a modern processor stalled synchronously on every cache miss, the ALU would spend over 95% of its time idling, destroying computing throughput. Chip architects resolved this through aggressive speculation: 1. Branch Predictors & Speculative Execution: The CPU predicts which direction an if branch will take with over 98% accuracy and executes instructions miles ahead of actual data readiness. 2. Out-of-Order Instruction Windows: While waiting for a slow DRAM load, the processor searches ahead in an instruction window of hundreds of instructions, executing independent instructions out of order and reordering the results before retirement. 3. The Microarchitectural Vulnerability (Spectre & Meltdown): In 2018, researchers discovered that speculative execution leaves physical footprints in the CPU cache. Even when a mispredicted branch is rolled back, the data loaded into the cache during speculative execution alters memory access timing, allowing attackers to measure microsecond latency differences (Flush+Reload) and read arbitrary kernel memory.

Experiment lab
We experimentally measure the latency difference between sequential array traversal and strided non-contiguous memory access. When iterating sequentially through an array, CPU hardware prefetchers stream contiguous cache lines into L1/L2 caches ahead of time, achieving high throughput. Striding with large intervals causes persistent cache line misses, demonstrating the critical impact of spatial locality. This empirical divergence proves why cache-conscious memory layouts are vital for high-throughput computing performance.

          Misconceptions
            

          • "Modern CPUs execute instructions strictly in the order they appear in assembly code." Modern processors use Out-of-Order (OoO) execution engines with Reorder Buffers (ROBs), executing instructions as soon as operands are ready and retiring them in program order.
            • 

          • "A 3.0 GHz processor is always 50% faster than a 2.0 GHz processor." Performance is governed by the Iron Law (Instructions * CPI * Clock Period). A 2.0 GHz CPU with higher IPC (Instructions Per Cycle) can vastly outperform a 3.0 GHz CPU that stalls frequently on cache misses.
            • 

          • "L1, L2, and L3 caches all use identical memory circuits." L1 cache uses high-transistor SRAM optimized for single-cycle latency (1 ns); L3 uses denser, slower SRAM (10-20 ns); main RAM uses high-density capacitor DRAM that requires periodic refreshing.
            • 

          • "Branch predictors only guess random directions on conditional jumps." Advanced branch predictors (like TAGE) maintain multi-kilobyte history tables tracking correlated patterns across thousands of past branches, exceeding 98% prediction accuracy.
            • 

          Where it breaks
          Computer architecture models break down when workloads defeat cache locality and branch predictors, such as graph traversals with irregular random pointer chasing. When every instruction experiences an L3 cache miss and branch misprediction, the processor pipeline constantly flushes and stalls, reducing effective CPU utilization to less than 5% of theoretical peak compute.
          In your real work
          Understanding computer architecture and cache hierarchies is essential for high-performance systems engineering. Game engine developers arrange components into Data-Oriented Design (structs of arrays) to saturate cache lines. High-frequency trading firms optimize code layouts to avoid L1 instruction cache misses, and database architects write lock-free ring buffers aligned to 64-byte boundaries to eliminate false sharing.
          Flash cards
          What is the Iron Law of Processor Performance?
          CPU Time = Instruction Count * CPI * Clock Period.
          What is AMAT in memory systems?
          Average Memory Access Time = Hit Time + (Miss Rate * Miss Penalty).
          What are the 4 C's of cache misses?
          Compulsory (cold start), Capacity (cache too small), Conflict (collision in set), Coherence (multicore invalidation).
          What is the difference between RISC and CISC?
          RISC uses simple, fixed-length load-store instructions optimized for single-cycle pipelining; CISC uses complex, variable-length multi-cycle instructions.
          What is a load-use data hazard?
          When an instruction immediately reads a register being loaded from memory, requiring a 1-cycle pipeline bubble even with forwarding.
          How do Spectre and Meltdown exploit speculative execution?
          By executing unauthorized loads past mispredicted branches; microarchitectural cache timing side channels leak the loaded secrets.
