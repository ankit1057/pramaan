The story

In 2020, as GPT-3 was released with 175 billion parameters, machine learning practitioners realized that running such a model required over 350 gigabytes of memory just to hold the weights in 16-bit floating point format. Even a modest 7-billion parameter open model demanded 14 to 28 gigabytes of VRAM, pricing out edge devices, phones, and consumer laptops. The solution lay in quantization: mapping high-precision 32-bit or 16-bit floating point numbers into compact 8-bit or 4-bit integers. Pioneered by Tim Dettmers with LLM.int8() and QLoRA, and popularized by Georgi Gerganov's llama.cpp project with GGUF block quantization formats, modern quantization allows 7B models to fit comfortably within 4 gigabytes of memory and run at 30 tokens per second on consumer smartphones with negligible perplexity degradation.

Say it simply

Quantization is the process of compressing neural network numbers from high precision (like 32-bit floats with decimals) into compact low precision numbers (like 8-bit or 4-bit integers). Just as compressing a raw photograph into a JPEG shrinks file size while preserving visual quality, quantizing weights slashes memory usage by up to 75% and speeds up text generation. By smartly handling extreme outlier values through block quantization and algorithms like AWQ, models run smoothly on consumer laptops and mobile phones without losing intelligence.

Say it precisely

Uniform affine quantization maps a continuous real value $x \in [\alpha, \beta]$ to a $b$-bit integer $q \in [q_{\min}, q_{\max}]$ where $q_{\min} = 0, q_{\max} = 2^b - 1$ for unsigned integers: $$q = \operatorname{clip}\left(\left\lfloor \frac{x}{S} \right\rceil + Z, q_{\min}, q_{\max}\right)$$ where the scale factor $S$ and zero-point integer $Z$ are defined as: $$S = \frac{\beta - \alpha}{q_{\max} - q_{\min}}, \qquad Z = \left\lfloor -\frac{\alpha}{S} \right\rceil$$ Dequantization reconstructs an approximation of the original float: $$\hat{x} = S \cdot (q - Z)$$

In symmetric block quantization (such as llama.cpp Q8_0 and Q4_0), weights are partitioned into small contiguous blocks (typically 32 numbers). For block $B$, zero-point is fixed to 0 ($Z = 0$), and scale is determined by maximum absolute value: $$d = \frac{\max_{x \in B} |x|}{q_{\max}}, \qquad q_i = \operatorname{clip}\left(\left\lfloor \frac{x_i}{d} \right\rceil, -q_{\max}, q_{\max}\right)$$ The GGUF container encapsulates model weights, hyperparameter metadata, and block scales in a single memory-mappable binary file designed for fast loading.

Why it's true

To understand why post-training quantization (PTQ) works without retraining, consider the error surface. Rounding high-precision weights introduces quantization noise $\mathbf{\epsilon} = \mathbf{w} - \hat{\mathbf{w}}$. The impact on layer activations is: $$\mathbf{y} - \hat{\mathbf{y}} = (\mathbf{W} - \hat{\mathbf{W}}) \mathbf{x} = \mathbf{\epsilon} \mathbf{x}$$ Under isotropic random assumptions, the noise variance scales with step size $S$: $\operatorname{Var}(\epsilon) = S^2 / 12$.

However, in large language models exceeding 6.7B parameters, activation distributions develop extreme outlier features: a tiny fraction (0.1%) of hidden channels exhibit magnitudes up to 100x larger than normal coordinates. In per-tensor quantization, these outliers blow up the scale factor $S = (\max - \min) / (2^b - 1)$, collapsing all non-outlier weights into just 1 or 2 quantization bins and degrading model perplexity catastrophically.

To resolve activation outliers, modern quantization relies on three core innovations: 1. Block Quantization (Q8_0, Q4_0): Dividing weights into independent blocks of 32 numbers isolates the dynamic range locally, preventing a single weight outlier from corrupting the entire row. 2. LLM.int8() (Mixed-Precision Decomposition): Decomposes matrix multiplications into an FP16 branch for the 0.1% outlier channels and an INT8 branch for the remaining 99.9% coordinates. 3. Activation-aware Weight Quantization (AWQ): Observes that not all weights are equally important; protecting the top 1% of weights corresponding to high-magnitude activation channels preserves perplexity even at 4-bit precision.

Memory footprint arithmetic is straightforward: $$\text{VRAM (Bytes)} = \text{Parameters} \times \frac{\text{Bits per weight}}{8} \times 1.2$$ where the $1.2$ factor accounts for KV cache and scratch activation buffers. A 7B parameter model requires 14 GB at 16-bit, but only 3.5 GB at 4-bit precision.

Write two functions:
1. quantize_affine(x_list, bits=8):
   - Let $q_{\min} = 0, q_{\max} = 2^{\text{bits}} - 1$.

   - Zero point: $Z = \operatorname{round}(-\alpha / S)$. Clip $Z \in [q_{\min}, q_{\max}]$.
   - For each $x_i$, compute $q_i = \operatorname{clip}(\operatorname{round}(x_i / S) + Z, q_{\min}, q_{\max})$.

2. dequantize_affine(q_list, scale, zero_point):
   - For each $q_i$, compute $\hat{x}_i = S \times (q_i - Z)$.
   - Return list of floats.

          Misconceptions
            

          • "Quantization to 4-bit always destroys model reasoning ability." Modern 4-bit methods like AWQ and GPTQ achieve perplexity within 0.1 to 0.2 points of FP16 baselines by protecting salient activation channels.
            • 

          • "Quantization speeds up the compute-heavy prefill phase as much as it speeds up decoding." Prefill is already compute-bound by GPU matrix units; quantization primarily speeds up single-token decoding by slashing memory bandwidth transfer volume.
            • 

          • "Uniform quantization works identically well across all weight layers." Attention output projections and FFN down-projections are much more sensitive to quantization noise than FFN up-projections, requiring mixed-precision or block strategies.
            • 

          • "An 8-bit integer uses less memory than an 8-bit floating point (FP8)." Both use exactly 8 bits (1 byte) of storage; they differ in dynamic range representation (linear steps for INT8 vs exponent/mantissa for FP8).
            • 

          Where it breaks
          Quantization breaks down when aggressive sub-3-bit compression destroys critical weight correlations, when high-magnitude activation outliers are forcibly clipped by naive per-tensor min-max quantization scaling, or when edge devices lack native INT4 integer dot-product tensor instructions, forcing dequantization overhead in software that negates memory bandwidth speed advantages.
          In your real work
          Quantisation is the foundational enabler for local on-device AI. Vision and language models quantised to 4-bit GGUF or AWQ formats drop from roughly 16 GB resident to under 4 GB, which is the difference between running on a field Android device with no connectivity and not running there at all.
          Flash cards
          What is uniform affine quantization?
          Mapping real numbers to integers via scale factor $S$ and zero-point $Z$: $q = \operatorname{clip}(\operatorname{round}(x/S) + Z)$.
          What is symmetric block quantization (Q8_0)?
          Dividing weights into small chunks (e.g. 32 numbers) and scaling symmetrically by $d = \max(|x|) / 127$ with zero-point fixed at 0.
          Why do large language models develop activation outliers?
          Certain hidden feature dimensions emerge during pre-training to track critical syntax or attention sinks, exhibiting values up to 100x larger than normal.
          How does AWQ (Activation-aware Weight Quantization) protect model accuracy?
          By identifying the 1% of weights corresponding to large activation magnitudes and preserving them with higher precision or scaling protection.
          How do you estimate single-token decode speed from memory bandwidth?
          Divide memory bandwidth (GB/s) by model weight memory footprint (GB).
          What is the GGUF file format?
          A binary container format developed for llama.cpp that packages model architecture metadata, vocabulary, and quantized weight tensors for fast memory-mapped loading.
