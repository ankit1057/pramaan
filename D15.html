The story

In the late 1960s, computer science pioneer Donald Knuth was studying an algorithm by Stephen Cook that recognized concatenations of reversed strings on a two-way deterministic pushdown automaton in linear time. Knuth was struck by the insight: why should searching for a pattern string of length $M$ inside a text of length $N$ take $O(N \cdot M)$ worst-case time? When a naive string search matches 99 characters of a 100-character pattern and fails on the 100th, it resets the text cursor back to character 2 and starts matching from scratch, blindly discarding all 99 characters of hard-won knowledge about the text.

Working independently, James H. Morris and Vaughan Pratt discovered that the pattern itself contains all the structural information needed to avoid ever backtracking the text cursor. By precomputing a table of "longest proper prefix that is also a suffix" (the $\pi$ or prefix function), the matcher shifts the pattern forward to the next plausible alignment instantly. Knuth, Morris, and Pratt published their joint paper in 1977, unveiling the KMP algorithm and establishing optimal $O(N + M)$ linear-time string search. Later, Richard Karp and Michael Rabin introduced rolling polynomial hashes, and Alfred Aho and Margaret Corasick generalized linear search to dictionary matching over thousands of keywords simultaneously using finite state automata.

Say it simply

Searching for a word in a book seems simple: compare letters until a mismatch happens. But if you match 'ELEPHANT' up to 'N' and miss on 'T', naive search moves forward by only one letter and re-reads everything. The Knuth-Morris-Pratt (KMP) algorithm pre-analyzes the word itself. If you mismatch, KMP knows exactly how much of the prefix matches what you just saw, sliding the word forward without ever re-reading a single letter of the text. Rabin-Karp treats words as numbers using a rolling hash, sliding a mathematical fingerprint across the text like an odometer.

Say it precisely

String algorithms achieve optimal time bounds by preprocessing strings into indexable automata or numerical digests:

  1. KMP Prefix Function $\pi$: For pattern $P[0 \dots m-1]$, $\pi[i]$ is the length of the longest proper prefix of $P[0 \dots i]$ that is also a suffix of $P[0 \dots i]$: $$\pi[i] = \max \{ k : 0 \le k < i \text{ and } P[0 \dots k-1] = P[i-k+1 \dots i] \}$$ Matching operates a deterministic automaton: on mismatch at $P[j]$, transition to $j = \pi[j-1]$. Total character comparisons are bounded by $2N$, achieving $O(N + M)$ worst-case time with zero text backtracking.

  2. Z-Algorithm: For string $S$, $Z[i]$ is the length of the longest substring starting at $S[i]$ that matches a prefix of $S$. Maintains a segment $[L, R]$ with maximal $R$ matching prefix $S[0 \dots R-L]$. If $i \le R$, $Z[i] \ge \min(R - i + 1, Z[i - L])$, computing the entire array in $O(|S|)$ time.

  3. Rabin-Karp Rolling Hash: Treats substring $S[i \dots i+m-1]$ as an integer in base $B$ modulo prime $P$: $$H(S[i+1 \dots i+m]) = \left( (H(S[i \dots i+m-1]) - S[i] \cdot B^{m-1}) \cdot B + S[i+m] \right) \pmod P$$ Enables $O(1)$ window updates. Expected search time is $O(N + M)$; worst-case $O(N \cdot M)$ on hash collisions, mitigated by verifying text equality upon hash match.

  4. Palindromic Substrings (Expand Around Center): Every palindrome has a center: $N$ single-character centers (odd length) and $N-1$ two-character centers (even length). Expanding outward takes $O(N^2)$ time and $O(1)$ auxiliary space.

Why it's true

Let us prove why the KMP prefix function guarantees linear $O(N + M)$ time complexity with zero text pointer backtracking. Let $i$ be the pointer into text $T$ of length $N$, and $j$ be the pointer into pattern $P$ of length $M$. In each iteration of the matching loop: 1. If $T[i] == P[j]$, both $i$ and $j$ increment by 1. 2. If $T[i] \ne P[j]$ and $j > 0$, $j$ is updated to $\pi[j-1]$, while $i$ remains unchanged. 3. If $T[i] \ne P[j]$ and $j == 0$, $i$ increments by 1.

Notice that the text pointer $i$ never decreases; it either increments or stays constant. In fact, $i$ increments at most $N$ times. What about $j$? The pointer $j$ starts at $0$ and increases only when $i$ increases (case 1), so $j$ can increase at most $N$ times in total. In case 2, $j$ decreases because $\pi[j-1] < j$. Since $j \ge 0$ always, the total number of decreases of $j$ cannot exceed the total number of increases. Therefore, case 2 can execute at most $N$ times throughout the entire execution. Thus, the total number of state transitions and character comparisons during matching is strictly upper-bounded by $2N$. Precomputing $\pi$ follows identical potential function analysis, bounded by $2M$. Hence, the overall time complexity is strictly $O(N + M)$.

Now consider why rolling hash in Rabin-Karp maintains correctness. Under modulo arithmetic with prime $P$, two distinct strings $S_1 \ne S_2$ can map to the same hash value $H(S_1) \equiv H(S_2) \pmod P$. By the Schwartz-Zippel lemma, the probability of two distinct strings of length $M$ having the same polynomial hash modulo random prime $P \approx 10^9$ is at most $M / P \approx 10^{-5}$. By verifying character equality whenever hashes match, Rabin-Karp guarantees zero false positives while preserving $O(N + M)$ expected run time.

          Misconceptions
            

          • "Naive string matching is fast enough for all practical cases" On repetitive strings like 'A'N matching 'A'(N/2)+'B', naive matching degrades to O(N^2) quadratic time, causing denial-of-service in parsers.
            • 

          • "KMP requires rewinding the text pointer on mismatch" The defining triumph of KMP is that the text pointer strictly increments or stays constant; only the pattern pointer falls back via pi[j-1].
            • 

          • "Rabin-Karp never makes mistakes without collision checks" Hash collisions are inevitable by the Pigeonhole Principle. Omitting the substring equality check allows false positives.
            • 

          • "Python strings are just ASCII byte arrays" Modern Python 3 uses Unicode (Flexible String Representation: Latin-1, UCS-2, UCS-4). Grapheme clusters (like emojis with skin tones) can span multiple code points.
            • 

          Where it breaks
          Classic string algorithms break down when dealing with complex Unicode normalization forms (NFC vs NFD), where 'e' + combining accent equals 'é' visually but differs in code points. For massive multi-gigabyte genomic sequences, in-memory table constructions for suffix automata exceed RAM, requiring compressed Burrows-Wheeler Transform (BWT) and FM-indexes.
          In your real work
          Knuth-Morris-Pratt and Aho-Corasick automate multi-pattern signature detection in antivirus engines (like ClamAV) and network intrusion detection systems (like Snort) searching thousands of malware signatures in packet streams. Rabin-Karp rolling polynomial hashes underpin rsync's bandwidth-efficient delta file transfer protocol, while Eugene Myers's difference algorithm powers version control diff engines like git diff.
          Flash cards
          What does the KMP prefix function pi[i] store?
          The length of the longest proper prefix of pattern[0..i] that is also a suffix of pattern[0..i].
          What is the time complexity of KMP search?
          O(N + M) worst-case time, where N is text length and M is pattern length.
          What is the Z-array definition?
          Z[i] is the length of the longest substring starting at s[i] that matches a prefix of string s.
          How does Rabin-Karp achieve O(1) rolling hash updates?
          Subtracts the outgoing character's high-order value, multiplies by base, and adds the incoming character modulo prime.
          How many expansion centers exist for palindromes in a string of length N?
          2N - 1 centers (N single characters and N - 1 adjacent character pairs).
          What is the Myers diff algorithm based on?
          Finding a shortest path in an edit graph from (0,0) to (N,M) using breadth-first greedy search.
