The story

In 1956, Dutch computer scientist Edsger W. Dijkstra was drinking coffee on a shopping terrace in Amsterdam with his fiancée Maria Debets. He had been tasked with creating an impressive demonstration for the unveiling of the ARMAC computer at the Mathematisch Centrum. Dijkstra decided to compute the shortest road route between 64 cities in the Netherlands. Sitting on the terrace, he designed the shortest path algorithm in twenty minutes without using pencil or paper, deliberately crafting the simplest possible logic so that the primitive computer could execute it without running out of vacuum tube memory.

During the same era, telecommunications researchers were struggling to design cost-effective telephone networks connecting hundreds of towns across North America. Joseph Kruskal at Bell Laboratories and Robert C. Prim developed algorithms to find a Minimum Spanning Tree (MST): a subgraph connecting every node with the absolute minimum total wire length. Robert Tarjan later proved that pairing Kruskal's greedy edge selection with Union-Find (Disjoint Set Union) using path compression and union by rank operates in amortized inverse Ackermann time $O(\alpha(N))$, arguably the closest computer science has ever come to a pure constant-time non-trivial data structure.

Say it simply

Shortest path algorithms find the fastest or cheapest route between two points when each road has a distance or travel time. Dijkstra's algorithm uses a priority queue to visit the closest unvisited city first, expanding outward like a radar sweep. If some roads have negative costs (like toll refunds or cashback), Bellman-Ford checks all roads repeatedly and alerts you if an infinite negative cash loop exists. A Minimum Spanning Tree connects all cities together using the least total asphalt, solved by Kruskal's algorithm using a Union-Find structure that tracks connected sets in nearly instant time.

Say it precisely

Formally, let $G = (V, E, w)$ be a weighted directed graph where $w: E \to \mathbb{R}$. The shortest path distance $\delta(s, v)$ satisfies the Triangle Inequality: $$\forall (u, v) \in E, \quad \delta(s, v) \le \delta(s, u) + w(u, v)$$ The relaxation operator updates tentative distance $d[v]$: $$\text{relax}(u, v): \quad \text{if } d[u] + w(u, v) < d[v] \implies d[v] = d[u] + w(u, v)$$

  • Dijkstra's Algorithm: Requires $w(e) \ge 0$. Uses a min-priority queue, extracting minimum $d[u]$ vertex and relaxing its outgoing edges. Runtime: $O((|V| + |E|) \log |V|)$.
  • Bellman-Ford Algorithm: Relaxes all $|E|$ edges $|V| - 1$ times. If a $|V|$-th relaxation pass succeeds in reducing any distance, a reachable negative weight cycle exists. Runtime: $O(|V| \cdot |E|)$.
  • Floyd-Warshall: Computes all-pairs shortest paths via dynamic programming $d^{(k)}[i][j] = \min(d^{(k-1)}[i][j], d^{(k-1)}[i][k] + d^{(k-1)}[k][j])$ in $O(|V|^3)$ time.
  • Cut Property for MST: For any cut $(S, V \setminus S)$, the minimum-weight edge crossing the cut belongs to every Minimum Spanning Tree.
  • Union-Find (DSU): Supports find(x) with path compression and union(x, y) with union by rank in amortized $O(\alpha(N))$ time per operation, where $\alpha$ is the inverse Ackermann function ($\alpha(N) \le 4$ for $N \le 10^{80}$).

Why it's true

Understanding weighted graph algorithms requires analyzing why Dijkstra's greedy choice holds for non-negative edges but fails with negative weights, and why the Cut Property guarantees Minimum Spanning Trees. First, let us prove Dijkstra's correctness. We claim that whenever a vertex $u$ is extracted from the priority queue, its tentative distance is exact: $d[u] = \delta(s, u)$.

We prove this by induction on the set of settled vertices $S$. Base case: initially $S = \{s\}$ with $d[s] = 0 = \delta(s, s)$. For the inductive step, let $u$ be the next vertex chosen from $V \setminus S$ with minimal $d[u]$. Suppose for contradiction that $d[u] > \delta(s, u)$. Consider the true shortest path $P$ from $s$ to $u$. Because $s \in S$ and $u \notin S$, there must exist an edge $(x, y)$ along $P$ such that $x \in S$ and $y \notin S$. By the inductive hypothesis, $d[x] = \delta(s, x)$. When $x$ was relaxed, $d[y]$ was set to at most $\delta(s, x) + w(x, y) = \delta(s, y)$.

Because all edge weights are non-negative ($w(e) \ge 0$), the subpath from $s$ to $y$ has length less than or equal to the full path to $u$: $\delta(s, y) \le \delta(s, u)$. Therefore: $$d[y] \le \delta(s, y) \le \delta(s, u) < d[u]$$ This inequality implies $d[y] < d[u]$. But our algorithm chose $u$ from $V \setminus S$ as the vertex with minimal tentative distance, which contradicts $d[y] < d[u]$ because $y \in V \setminus S$. Thus, $d[u]$ must equal $\delta(s, u)$. Notice that this proof crucially relies on $w(e) \ge 0$; if an edge weight along the path past $y$ were negative, $\delta(s, u)$ could be smaller than $\delta(s, y)$, completely invalidating the greedy choice.

Now consider the Cut Property for Minimum Spanning Trees. Let $T$ be an MST of $G$, and let $(S, V \setminus S)$ be any partition of $V$. Let $e = (u, v)$ be the edge of minimum weight crossing this cut. If $e \in T$, the property holds trivially. If $e \notin T$, adding $e$ to $T$ creates a unique cycle $C$. Because $u \in S$ and $v \in V \setminus S$, the cycle $C$ must cross the cut again via some other edge $e' = (x, y) \ne e$.

Consider the spanning tree $T' = (T \setminus \{e'\}) \cup \{e\}$. Because $e$ is the minimum weight crossing edge, $w(e) \le w(e')$. Therefore: $$w(T') = w(T) - w(e') + w(e) \le w(T)$$ Because $T$ was already a minimum spanning tree, $w(T')$ cannot be strictly smaller than $w(T)$, which forces $w(e) = w(e')$ and $w(T') = w(T)$. Thus $T'$ is also an MST containing $e$, proving the Cut Property.

Oracle lab

The ground truth for shortest path algorithms is governed by relaxation monotonicity and distance triangle inequalities. After running Dijkstra or Bellman-Ford, every edge $(u, v) \in E$ must satisfy $d[v] \le d[u] + w(u, v)$ with equality holding along true shortest path edges. For Minimum Spanning Trees, Kruskal's algorithm serves as a structural oracle: the returned tree must contain exactly $|V| - 1$ edges, possess no cycles (verified via DFS or Union-Find), and span all connected vertices with minimal sum of weights.

          Misconceptions
            

          • "Dijkstra's algorithm works with negative edge weights as long as there are no negative cycles." False. Even a single negative edge can cause Dijkstra to settle a vertex permanently with an incorrect distance because its greedy assumption $\delta(s, u) \le \delta(s, v)$ breaks down.
            • 

          • "Bellman-Ford is slower than Dijkstra, so it should never be used." Bellman-Ford handles arbitrary negative edge weights and reliably detects arbitrage or negative cycles, which Dijkstra cannot do.
            • 

          • "A Minimum Spanning Tree is unique." If multiple edges share the same weight, there can be multiple distinct valid Minimum Spanning Trees with identical minimum total weight.
            • 

          • "Union-Find operations take strict O(1) time." They take amortized $O(lpha(N))$ time where $lpha$ is the inverse Ackermann function. While $lpha(N) \le 4$ for all physical values, it is asymptotically distinct from $O(1)$.
            • 

          Where it breaks
          Shortest path algorithms break when running on planetary road networks (millions of intersections in Google Maps). Running Dijkstra across the continent of North America visits tens of millions of nodes and takes several seconds. Modern navigation engines solve this using Contraction Hierarchies (precomputing shortcut edges along highways), Transit Node Routing, and bidirectional A* with Landmark heuristics (ALT).
          In your real work
          Internet routing protocols (OSPF, IS-IS) use Dijkstra's algorithm to compute shortest path routes across autonomous systems. BGP (Border Gateway Protocol) uses path-vector routing similar to Bellman-Ford. High-frequency cryptocurrency trading desks run Bellman-Ford on logarithmic currency exchange cross-rates to detect triangular arbitrage opportunities (negative cycles).
          Flash cards
          Why does Dijkstra's algorithm fail on graphs with negative edge weights?
          Because Dijkstra assumes that once a vertex is popped from the priority queue, its distance is final and can never be improved by extending a longer path.
          How does Bellman-Ford detect negative weight cycles?
          By running a $|V|$-th relaxation pass: if any distance can still be decreased after $|V|-1$ passes, a reachable negative cycle must exist.
          What is the Cut Property for Minimum Spanning Trees?
          For any partition of vertices into two sets $S$ and $V \setminus S$, the minimum weight edge crossing the cut must belong to an MST.
          What two optimizations give Union-Find its inverse Ackermann O(alpha(N)) runtime?
          Path compression (flattens trees during find) and union by rank (attaches shorter trees under taller trees during union).
          What is the time complexity of Kruskal's algorithm?
          $O(|E| \log |E|)$ dominated by sorting the edges by weight.
          What does the Floyd-Warshall algorithm compute and in what time complexity?
          All-pairs shortest paths for every pair of vertices in $O(|V|^3)$ time using 3 nested loops.
          Stop when
          You can prove the Cut Property using an exchange argument, implement Dijkstra with priority queues, and detect negative cycles with Bellman-Ford without references.
