The story

In late 2023, independent researchers auditing popular open-source LLM leaderboards made an embarrassing discovery: several top-ranking models that purportedly matched or exceeded GPT-4 on GSM8K and HumanEval benchmarks were utterly incapable of solving trivial variations of the same problems when numbers or variable names were altered. The models had not achieved superhuman reasoning; their creators had accidentally or deliberately contaminated pre-training datasets with evaluation questions. For decades, machine learning evaluation operated under the classical assumption of independent and identically distributed (i.i.d.) train/test splits. In the era of web-scale scraped corpora, benchmark contamination, LLM-as-a-judge biases, and Goodhart's law have transformed model evaluation from a routine test script into a high-stakes forensic discipline requiring rigorous statistical hypothesis testing and leak-free benchmarking suites.

Say it simply

Evaluating artificial intelligence is much harder than giving a student an exam. If the questions from the exam accidentally leaked into the model's training textbooks, the AI will get an A+ by simply memorizing answers rather than truly understanding. Using another AI to grade answers sounds easy, but AI judges often suffer from strong biases—like preferring longer, wordier answers or favoring whichever answer was shown first. To measure AI truthfully, researchers use strict statistical confidence intervals, blind human evaluation rubrics, and hold-out tests that change constantly over time.

Say it precisely

  1. The Safety Net (Confidence Intervals): If a robot gets 9 out of 10 math questions right today, we can't promise it will score exactly 90 percent tomorrow! We use a math safety net to calculate a safe guess, saying: "We are extremely sure the robot's true skill is somewhere between 60 percent and 98 percent."
  2. The Tie-Breaker (Paired Tests): If you want to know if Robot A is smarter than Robot B, total scores aren't enough. We only look at the questions where they disagreed! If Robot A solved 5 puzzles that Robot B failed, and Robot B solved 0 puzzles that Robot A failed, Robot A is definitely the winner.
  3. The Agreement Score (Cohen's Kappa): If two teachers grade a test by flipping coins, they will accidentally give the same grade half the time just by luck! The "Agreement Score" is a clever math trick that subtracts all the lucky coincidences so we know if the teachers are actually using the same rules to grade.

Why it's true

Why do super smart robots sometimes seem like total frauds?

  1. The Target Trap: If you tell a classroom they will only ever be tested on spelling the word "apple," they will all get an A+ on the test, but none of them will know how to spell "banana." When a robot's creator only cares about getting a high score on one specific test, the test completely stops measuring real intelligence!
  2. The Stolen Answer Key (Contamination): The robot read the entire internet to get smart. But if someone accidentally posted the test answers on a website three years ago, the robot just memorized the answers! The only way to prove a robot is truly smart is to test it on brand-new puzzles invented after the robot was built.
  3. Silly Robot Judges: Sometimes we ask a giant robot to grade a smaller robot's homework. But robot judges are incredibly silly! They almost always pick the answer they read first (Option A). They always give a better grade to the student who wrote a longer, fluffier essay, even if a short answer was better. And they love giving the highest grades to robots built by their own creators!

Oracle lab

To verify that evaluation metrics and statistical tests maintain mathematical integrity, we build an empirical evaluation oracle. The oracle computes Wilson score intervals and verifies that coverage probability matches nominal 95% confidence levels across binomial trials. Furthermore, the oracle verifies that Cohen's kappa evaluates to exactly 1.0 for perfect agreement, 0.0 for chance agreement, and negative values for systematic disagreement.

Write calculate_wilson_ci(correct_count, total_count, confidence=0.95):
Inputs:
- correct_count: Number of correctly predicted test instances.
- total_count: Total number of test instances (at least 1).
- confidence: Confidence level (default 0.95, corresponding to z = 1.95996).
  - For confidence=0.90, use z = 1.64485.
  - For confidence=0.95, use z = 1.95996.
  - For confidence=0.99, use z = 2.57583.


Formula:
Center S = (p_hat + z^2 / (2n)) / (1 + z^2 / n), and Margin M = (z * sqrt(p_hat * (1 - p_hat) / n + z^2 / (4 * n^2))) / (1 + z^2 / n).
Lower = max(0.0, S - M), and Upper = min(1.0, S + M).
Return dictionary:
{"accuracy": round(p_hat, 4), "ci_lower": round(Lower, 4), "ci_upper": round(Upper, 4), "margin": round(M, 4)}.

    Write paired_bootstrap_test(results_a, results_b, num_bootstrap=1000, seed=42):
Inputs:
- results_a: List of 0s and 1s indicating correctness for Model A on N test samples.
- results_b: List of 0s and 1s indicating correctness for Model B on the exact same N samples.
- num_bootstrap: Number of bootstrap resamples (default 1000).
- seed: Random seed for reproducibility.
    

    Requirements:
1. Observed accuracy difference: mean(results_b) - mean(results_a).
2. For each bootstrap iteration:
   - Sample N indices with replacement uniformly from 0 to N-1.
   - Compute resampled accuracy for A and B.
   - Record difference: delta = acc_b - acc_a.
3. Compute empirical p-value for the hypothesis that Model B is superior to Model A:
   Compute p-value as the fraction of bootstrap iterations where delta is less than or equal to 0.
4. Return dictionary:
   {"acc_a": round(mean_a, 4), "acc_b": round(mean_b, 4), "delta_obs": round(Delta_obs, 4), "p_value": round(p_val, 4), "is_significant_05": bool(p_val < 0.05)}.

def test_bootstrap_identical_models():
    a = [1, 0, 1, 0, 1] * 20

      Write calculate_cohens_kappa(rater1_labels, rater2_labels, categories=[0, 1]):
Inputs:
- rater1_labels: List of categorical decisions from Rater 1 (e.g., human expert).
- rater2_labels: List of categorical decisions from Rater 2 (e.g., LLM-as-a-Judge).
- categories: List of unique allowed category values (default [0, 1]).
      

      Formula:
1. Observed agreement: fraction of samples where rater 1 and rater 2 agree.
2. For each category:
   - Proportion of times Rater 1 picked that category.
   - Proportion of times Rater 2 picked that category.
3. Chance agreement: sum of product of rater proportions across all categories.
4. Cohen's kappa:
   Kappa = (P_observed - P_expected) / (1.0 - P_expected).
   (If P_expected == 1.0, return kappa = 1.0).
5. Return dictionary:
   {"observed_agreement": round(P_o, 4), "chance_agreement": round(P_e, 4), "kappa": round(kappa, 4)}.

def test_chance_agreement():
    # 50% ones, completely independent
    r1 = [1, 1, 0, 0]
    r2 = [1, 0, 1, 0]
    res = calculate_cohens_kappa(r1, r2)
    # 2 matches out of 4 -> P_o = 0.5
    # P_e = 0.5 * 0.5 + 0.5 * 0.5 = 0.5
    assert res["observed_agreement"] == 0.5
    assert res["chance_agreement"] == 0.5
    assert res["kappa"] == 0.0 # Exactly chance level

def test_systematic_disagreement():
    r1 = [1, 1, 1, 1]
    r2 = [0, 0, 0, 0]
    res = calculate_cohens_kappa(r1, r2)
    assert res["observed_agreement"] == 0.0
    assert res["kappa"] <= 0.0

        Write audit_judge_biases(judge_evaluations):
Audit an automated LLM evaluation protocol for position bias and verbosity bias across paired model comparisons:
Input judge_evaluations: List of dicts, each representing a pair of candidate responses evaluated twice:
- response_x_len: Word count of candidate X (int).
- response_y_len: Word count of candidate Y (int).
- order1_winner: Winner string ('X' or 'Y') when presented as Option A = X, Option B = Y.
- order2_winner: Winner string ('X' or 'Y') when presented in reversed order Option A = Y, Option B = X.
        

        Requirements:
1. Position Bias:
   - In order 1, Option A was X. If order1_winner == 'X', Option A won.
   - In order 2, Option A was Y. If order2_winner == 'Y', Option A won.
   - Total Option A wins across both orders divided by total decisions (2 * N).
   - Report option_a_win_rate.
2. Consistency Rate:
   - A pair is consistent if the same candidate won both runs (order1_winner == order2_winner).
   - Report consistency_rate = consistent_pairs / N.
3. Verbosity Bias:
   - For all consistent pairs where lengths differed (response_x_len != response_y_len):
     count how many times the longer response won.
   - Report longer_response_win_rate (return 0.5 if no valid pairs).
4. Return dictionary:
   {"total_pairs": N, "option_a_win_rate": round(a_rate, 4), "consistency_rate": round(c_rate, 4), "longer_win_rate": round(l_rate, 4)}.

          Misconceptions
            

          • "A model with 90% accuracy on GSM8K will reliably solve 90% of arithmetic tasks in production." GSM8K is heavily contaminated across public internet crawls; models frequently fail on identical arithmetic problems when numbers are changed.
            • 

          • "LLM-as-a-Judge is an objective ground truth benchmark." Automated judges inherit severe position bias (favoring Option A), verbosity bias (favoring wordy answers), and family preference biases.
            • 

          • "A 2% benchmark accuracy improvement is always statistically significant." With a typical test set of 500 questions, a 2% gain has a 95% confidence margin of plus or minus 3.5 percent, making it indistinguishable from random noise without paired hypothesis testing.
            • 

          • "Decontamination can be achieved by simply filtering exact string matches." Paraphrased questions, reordered math steps, and syntactic variations easily bypass naive string matching, requiring n-gram embedding checks.
            • 

          Where it breaks
          Evaluation pipelines break down when test datasets are absorbed into public pre-training web scrapes without decontamination auditing, when LLM judges suffer from position and verbosity biases that swamp true model quality differences, or when teams optimize single scalar leaderboard metrics subject to Goodhart's law, degrading general task competence. Furthermore, adversarial test prompts designed with subtle mathematical perturbations can systematically fool confidence intervals on production model safety benchmarks.
          In your real work
          Serious AI labs run rigorous statistical evaluation suites and decontamination scanners before releasing a model. An on-device model should be evaluated with McNemar's test against expert-certified ground truth, because a benchmark that has leaked into training will otherwise inflate a readiness claim that field use immediately contradicts.
          Flash cards
          What is test set contamination?
          When benchmark test questions or solutions leak into the pre-training or fine-tuning datasets, causing models to memorize answers rather than generalize.
          Why use the Wilson score interval instead of the Wald interval?
          The Wald interval assumes normal distribution and produces invalid bounds (above 1.0 or below 0.0) near extreme accuracies or for small sample sizes; Wilson maintains valid coverage.
          What is Cohen's kappa?
          A statistical metric measuring agreement between two raters (e.g. human vs LLM judge) normalized by the agreement expected purely by random chance.
          What is position bias in LLM-as-a-judge?
          The tendency of automated judges to disproportionately favor whichever answer is presented first (as Option A).
          How does paired bootstrap testing compare two models?
          By resampling test set indices with replacement and calculating the empirical probability that Model B fails to outperform Model A.
          What is Goodhart's Law in machine learning?
          When a specific benchmark metric becomes the primary optimization target, models overfit to its quirks and the metric loses its value as a measure of intelligence.
          Stop when
          You can compute Wilson score confidence intervals, execute paired bootstrap superiority testing, and audit LLM judges for position and verbosity biases.
