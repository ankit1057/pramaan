The story

In late 2022, as large language models exploded into mainstream production, infrastructure engineers confronted a harsh computational reality: generating text from an LLM token by token was excruciatingly slow and memory-bound. During prefill, the model processed the entire input prompt in a single parallel burst, saturating GPU compute cores. But during autoregressive decoding, generating each subsequent token required passing every single weight matrix through high-bandwidth memory (HBM) just to compute a single matrix-vector multiplication. Worse, recomputing past attention keys and values for every new token resulted in quadratic $O(N^2)$ overhead. The introduction of the Key-Value (KV) cache eliminated redundant recomputation by caching past states in memory, but introduced an acute memory bottleneck. Breakthrough decoding strategies—temperature scaling, nucleus (top-p) sampling, speculative decoding with draft models, and grammar-constrained decoding—transformed LLM inference into a finely tuned science.

Say it simply

When an AI generates a response, it predicts text one word piece at a time. At each step, the model calculates scores for thousands of possible next tokens and converts them into probabilities. You can control creativity using temperature, top-k, and top-p sampling, which filter out improbable words. To avoid re-reading the entire conversation history from scratch for every new word, the system caches past computational results in a Key-Value (KV) cache. Speculative decoding speeds this up even further by letting a tiny, fast model draft several words ahead, which the main model verifies in a single parallel check.

Say it precisely

Let $\mathbf{z}_t \in \mathbb{R}^V$ denote the unnormalized logit vector output by the language model at step $t$ over vocabulary $\mathcal{V}$ of size $V$. The sampling distribution is computed via temperature-scaled softmax: $$P(x_t = i \mid x_{<t}) = \frac{\exp(z_{t, i} / T)}{\sum_{j=1}^V \exp(z_{t, j} / T)}$$ where $T > 0$ is the sampling temperature. - In Top-$k$ filtering, the candidate set is restricted to $\mathcal{K} = \operatorname{argtopk}(\mathbf{z}_t, k)$, setting probabilities of all other tokens to zero before renormalizing. - In Top-$p$ (nucleus) filtering, tokens are sorted in descending order of probability $p_{(1)} \ge p_{(2)} \dots \ge p_{(V)}$, and the smallest set $\mathcal{P} = \{1, \dots, m\}$ is selected such that $\sum_{j=1}^m p_{(j)} \ge p$.

In Speculative Decoding (Leviathan et al. 2023), a fast draft model $q$ proposes $\gamma$ tokens $x_1, \dots, x_\gamma$. The target model $p$ evaluates all tokens in a single parallel forward pass. Token $x_i$ is accepted with exact probability: $$\alpha = \min\left(1, \frac{p(x_i \mid x_{<i})}{q(x_i \mid x_{<i})}\right)$$ If a token is rejected at index $j$, generation halts, and a replacement token is sampled from the normalized residual distribution: $$P_{\text{residual}}(x) = \frac{\max(0, p(x) - q(x))}{\sum_{x'} \max(0, p(x') - q(x'))}$$ guaranteeing that the output distribution matches the target model $p$ identically.

Why it's true

To understand the performance dynamics of LLM inference, consider the distinction between the prefill phase and the decode phase. 1. Prefill (Compute-Bound): The user prompt of length $P$ is processed in parallel. Matrix-matrix multiplications have high arithmetic intensity (FLOPs per byte of memory accessed), fully saturating GPU tensor cores. 2. Decode (Memory-Bound): Generation proceeds autoregressively, one token at a time. For each new token, the entire model weight tensor of size $W$ bytes must be loaded from memory into registers to perform matrix-vector multiplication. The time required to generate one token is bounded by memory bandwidth: $$t_{\text{token}} \approx \frac{\text{Model Weights (Bytes)}}{\text{Memory Bandwidth (Bytes/sec)}}$$ On an NVIDIA A100 GPU (2,000 GB/s bandwidth), loading a 14 GB 7B FP16 model takes $14 / 2000 = 7.0$ milliseconds per token, capping single-batch throughput at ~140 tokens/sec regardless of how many TFLOPs the GPU possesses.

The KV Cache prevents quadratic recomputation. At step $t$, rather than recalculating keys and values for all $t$ prior tokens, we cache past $\mathbf{K}$ and $\mathbf{V}$ tensors. The memory footprint of the KV cache grows linearly with sequence length: $$\text{Memory}_{\text{KV}} = 2 \times n_{\text{layers}} \times n_{\text{heads}} \times d_k \times \text{seq\_len} \times \text{bytes\_per\_elem} \times \text{batch\_size}$$ For a 70B model with sequence length 4,096 in FP16, the KV cache requires over 2.5 GB per concurrent user.

In speculative decoding, the draft model runs $\gamma$ steps cheaply. When the target model verifies all $\gamma$ tokens simultaneously, it runs in the compute-bound regime. Because the acceptance criterion $\min(1, p/q)$ and residual distribution $\max(0, p-q)$ mathematically preserve the target distribution, speculative decoding achieves 2x to 3x wall-clock speedups with zero loss in output quality.

Write filter_and_sample_probs(logits, temperature=1.0, top_k=0, top_p=1.0):
Inputs:
- logits: 1D list of floats representing unnormalized log probabilities.
- temperature: Positive float scaling factor (default 1.0).
- top_k: Integer $k \ge 0$; if $k > 0$, retain only the $k$ highest logits, setting others to $-\infty$.
- top_p: Float $p \in (0, 1.0]$; retain smallest set of top tokens whose cumulative probability $\ge p$.


Algorithm:
1. Scale logits: $z_i' = z_i / \text{temperature}$.
2. If top_k > 0, find the $k$-th largest value and set all logits below it to $-10^9$.
3. Compute softmax probabilities $P(i) = \frac{\exp(z_i' - \max z')}{\sum \exp(z' - \max z')}$.
4. If top_p < 1.0:
   - Sort probabilities in descending order with indices.
   - Compute cumulative sum.
   - Find the cutoff index where cumulative sum first exceeds or equals top_p.
   - Set probabilities beyond this cutoff to $0.0$.
   - Renormalize remaining probabilities to sum to $1.0$.
5. Return the final normalized probability list of the same length as logits.

    assert p[2] == 0.0 and p[3] == 0.0 and p[4] == 0.0

    # 0.993 >= 0.95, so only the first token is kept
    assert p[0] == 1.0
    assert p[1] == 0.0 and p[2] == 0.0

Write kv_cache_attention_step(q_new, k_new, v_new, k_cache, v_cache):
Inputs:
- q_new: Query vector for new token, length $d_k$.
- k_new: Key vector for new token, length $d_k$.
- v_new: Value vector for new token, length $d_v$.
- k_cache: List of existing cached key vectors (length $T$).
- v_cache: List of existing cached value vectors (length $T$).
    

    Requirements:
1. Append k_new to k_cache and v_new to v_cache in-place.
2. The updated cache now contains $T+1$ keys and values.
3. Compute attention score of q_new against all keys in k_cache:
   $$s_j = \frac{\mathbf{q}_{\text{new}} \cdot \mathbf{k}_j}{\sqrt{d_k}}, \quad j \in \{0, \dots, T\}$$
4. Compute numerically stable softmax weights:
   $$a_j = \frac{\exp(s_j - \max s)}{\sum \exp(s - \max s)}$$
5. Compute output vector $\mathbf{o} = \sum_{j=0}^T a_j \mathbf{v}_j$.
6. Return tuple (o, a) where o is list of floats (length $d_v$) and a is attention weights list (length $T+1$).

Write speculative_verify_token(token_draft, p_probs, q_probs, uniform_random_val):
Inputs:
- token_draft: Proposed token ID (int).
- p_probs: Target model probability distribution (list of floats summing to 1.0).
- q_probs: Draft model probability distribution (list of floats summing to 1.0).
- uniform_random_val: Random float $U \in [0.0, 1.0)$ for acceptance decision.
      

      Requirements:
1. Compute acceptance probability $\alpha = \min\left(1.0, \frac{p(\text{token\_draft})}{q(\text{token\_draft})}\right)$.
2. If uniform_random_val < alpha:
   - Token is accepted. Return {"accepted": True, "token": token_draft, "residual_dist": None}.
3. If uniform_random_val >= alpha:
   - Token is rejected.
   - Compute residual distribution:
     $$R(i) = \max(0.0, p_i - q_i)$$
   - Normalize: $R_{\text{norm}}(i) = R(i) / \sum_j R(j)$.
   - Return {"accepted": False, "token": None, "residual_dist": R_norm}.

        def test_speculative_always_accept():
    # If p(x) >= q(x), alpha = 1.0, always accept regardless of U
    p = [0.8, 0.2]
    q = [0.4, 0.6]

    assert res["accepted"] is True
    assert res["token"] == 0

def test_speculative_reject_residual():
    # token 1: p=0.2, q=0.6 -> alpha = 0.2 / 0.6 = 0.333
    p = [0.8, 0.2]
    q = [0.4, 0.6]
    res = speculative_verify_token(1, p, q, uniform_random_val=0.5) # 0.5 > 0.333 -> Reject
    assert res["accepted"] is False
    assert res["token"] is None
    # Residual: p - q -> max(0, 0.8 - 0.4) = 0.4; max(0, 0.2 - 0.6) = 0.0
    # Normalized residual must place 100% mass on token 0
    assert abs(res["residual_dist"][0] - 1.0) < 1e-5
    assert abs(res["residual_dist"][1] - 0.0) < 1e-5

def test_speculative_partial_accept():
    p = [0.5, 0.5]
    q = [0.8, 0.2]
    # token 0: alpha = 0.5 / 0.8 = 0.625
    res1 = speculative_verify_token(0, p, q, uniform_random_val=0.4)
    assert res1["accepted"] is True
    res2 = speculative_verify_token(0, p, q, uniform_random_val=0.7)
    assert res2["accepted"] is False

          def test_repetition_penalty():
    logits = [2.0, -2.0, 5.0]
    history = [0, 1]
    # token 0 is positive (2.0) -> 2.0 / 2.0 = 1.0
    # token 1 is negative (-2.0) -> -2.0 * 2.0 = -4.0

    assert abs(penalized[0] - 1.0) < 1e-6
    assert abs(penalized[1] - (-4.0)) < 1e-6
    assert abs(penalized[2] - 5.0) < 1e-6

def test_grammar_masking():
    logits = [10.0, 20.0, 30.0]
    mask = [True, False, True] # token 1 is disallowed by grammar

    assert masked[0] == 10.0
    assert masked[1] == -1e9
    assert masked[2] == 30.0

def test_both_applied():

          Misconceptions
            

          • "Speculative decoding alters the output text distribution of the target model." Speculative decoding uses exact acceptance probabilities and residual resampling that mathematically guarantee the final output distribution is indistinguishable from running the target model directly.
            • 

          • "Decoding speed is limited by GPU TFLOPs computing power." Single-token decoding is heavily memory-bandwidth bound; the GPU spends over 90% of its time waiting to transfer model weights from VRAM to compute cores.
            • 

          • "Greedy decoding (temperature 0) always produces the most coherent and natural text." Greedy search frequently gets trapped in repetitive loops; sampling with moderate temperature and nucleus filtering consistently produces higher human-evaluated quality.
            • 

          • "KV caching decreases overall GPU VRAM usage." The KV cache eliminates redundant computation but consumes significant additional VRAM that scales linearly with batch size and sequence length.
            • 

          Where it breaks
          LLM inference breaks down when concurrent requests exceed available KV cache memory leading to out-of-memory crashes, when low-temperature sampling triggers pathological phrase repetition loops, or when speculative decoding draft models have low acceptance rates (e.g. <30%), causing validation overhead that makes generation slower than standard decoding.
          In your real work
          Production LLM serving engines such as vLLM, TensorRT-LLM and llama.cpp rely on paged KV caches, speculative decoding and grammar-constrained logit masking. On-device, grammar masking is what guarantees a structurally valid JSON response first time, because there is no server to re-ask when the output does not parse.
          Flash cards
          What is the difference between prefill and decode phases?
          Prefill processes prompt tokens in parallel (compute-bound); decode generates one token at a time sequentially (memory-bound).
          Why does single-batch LLM decoding underutilize GPU compute cores?
          Because loading gigabytes of model weights to perform a single token matrix-vector multiplication is bottlenecked by memory bandwidth.
          What does the KV cache store?
          Past Key and Value activation vectors across attention layers, preventing quadratic $O(N^2)$ recomputation during autoregressive generation.
          How does speculative decoding achieve speedup without quality loss?
          A small draft model proposes multiple tokens cheaply, which the target model verifies in a single parallel step with exact acceptance-rejection criteria.
          What is nucleus (top-p) sampling?
          Sampling from the smallest set of high-probability tokens whose cumulative mass exceeds threshold $p$.
          How does repetition penalty discourage loops?
          By dividing positive logits (or multiplying negative logits) of previously generated tokens by penalty scalar $lpha > 1.0$.
