The story

In late 2022, as large language models exploded into mainstream production, infrastructure engineers confronted a harsh computational reality: generating text from an LLM token by token was excruciatingly slow and memory-bound. During prefill, the model processed the entire input prompt in a single parallel burst, saturating GPU compute cores. But during autoregressive decoding, generating each subsequent token required passing every single weight matrix through high-bandwidth memory (HBM) just to compute a single matrix-vector multiplication. Worse, recomputing past attention keys and values for every new token resulted in slow quadratic overhead. The introduction of the Key-Value (KV) cache eliminated redundant recomputation by caching past states in memory, but introduced an acute memory bottleneck. Breakthrough decoding strategies—temperature scaling, nucleus (top-p) sampling, speculative decoding with draft models, and grammar-constrained decoding—transformed LLM inference into a finely tuned science.

Say it simply

When an AI generates a response, it predicts text one word piece at a time. At each step, the model calculates scores for thousands of possible next tokens and converts them into probabilities. You can control creativity using temperature, top-k, and top-p sampling, which filter out improbable words. To avoid re-reading the entire conversation history from scratch for every new word, the system caches past computational results in a Key-Value (KV) cache. Speculative decoding speeds this up even further by letting a tiny, fast model draft several words ahead, which the main model verifies in a single parallel check.

Say it precisely

  1. The Silliness Thermostat (Temperature): When a robot picks the next word, it assigns a score to every word in the dictionary. The "temperature" dial controls how creative the robot is. Turn it low, and the robot is perfectly boring and predictable. Turn it high, and the robot picks wild, silly, unexpected words!
  2. The Top Choices (Top-K and Top-P): Sometimes the robot has 10,000 words to choose from. "Top-K" tells the robot: "Only look at the top 10 best words, throw the rest in the trash!" "Top-P" tells the robot: "Grab the best words until you have a group that is 90 percent likely to be correct, then stop." This stops the robot from ever saying total gibberish.
  3. The Fast Helper (Speculative Decoding): Imagine a super-fast but sloppy assistant who instantly scribbles down five guesses for the next words. The giant, slow boss robot reads all five words at the exact same time. If the assistant guessed right, the boss approves them all instantly! If the assistant messed up word three, the boss fixes word three and erases the rest.

Why it's true

Why is talking to a giant robot so incredibly slow, even when the robot has a supercomputer brain?

  1. The Library Traffic Jam (Memory Bound): Reading your prompt is super fast because the robot reads it all at once. But when it writes an answer, it writes one single word at a time. To guess just one word, the robot has to run to the library, load billions of rules into its brain, guess the word, and put the rules back. Most of the time, the supercomputer brain is doing absolutely nothing—it is just stuck in traffic waiting for the library books to load!
  2. The Sticky Note Board (KV Cache): When guessing word number 100, the robot shouldn't have to re-read the first 99 words. To save time, it writes down the meaning of the old words on sticky notes and leaves them on a whiteboard. This makes the robot much faster, but for huge conversations, the whiteboard gets completely covered in sticky notes and runs out of space!
  3. The Speedy Boss (Why the helper works): The sloppy assistant trick is amazing because the boss robot checks the assistant's work perfectly. The story quality is exactly identical to the boss writing it alone. But because the boss can check five words in the exact same time it takes to write one word, the whole team works three times faster and avoids all the library traffic jams!

Write filter_and_sample_probs(logits, temperature=1.0, top_k=0, top_p=1.0):
Inputs:
- logits: 1D list of floats representing unnormalized log probabilities.
- temperature: Positive float scaling factor (default 1.0).
- top_k: Integer at least 0; if greater than 0, retain only the top k highest logits, setting others to -1e9.
- top_p: Float between 0.0 and 1.0; retain smallest set of top tokens whose cumulative probability is at least p.


Algorithm:
1. Scale logits by temperature: z / temperature.
2. If top_k > 0, find the k-th largest value and set all logits below it to -1e9.
3. Compute softmax probabilities over the scaled logits.
4. If top_p < 1.0:
   - Sort probabilities in descending order with indices.
   - Compute cumulative sum.
   - Find the cutoff index where cumulative sum first exceeds or equals top_p.
   - Set probabilities beyond this cutoff to 0.0.
   - Renormalize remaining probabilities to sum to 1.0.
5. Return the final normalized probability list of the same length as logits.

def test_top_k():
    logits = [10.0, 8.0, 6.0, 4.0, 2.0]
    p = filter_and_sample_probs(logits, top_k=2)
    assert p[0] > 0 and p[1] > 0
    assert p[2] == 0.0 and p[3] == 0.0 and p[4] == 0.0
    assert abs(sum(p) - 1.0) < 1e-5

def test_top_p_nucleus():
    logits = [10.0, 5.0, 1.0] # probabilities will be roughly [0.993, 0.0067, 0.0001]
    p = filter_and_sample_probs(logits, top_p=0.95)
    # 0.993 >= 0.95, so only the first token is kept
    assert p[0] == 1.0
    assert p[1] == 0.0 and p[2] == 0.0

Write kv_cache_attention_step(q_new, k_new, v_new, k_cache, v_cache):
Inputs:
- q_new: Query vector for new token, length d_k.
- k_new: Key vector for new token, length d_k.
- v_new: Value vector for new token, length d_v.
- k_cache: List of existing cached key vectors.
- v_cache: List of existing cached value vectors.
    

    Requirements:
1. Append k_new to k_cache and v_new to v_cache in-place.
2. The updated cache now contains all past keys and values plus the new one.
3. Compute attention score of q_new against all keys in k_cache:
   Compute attention scores: s_j = (q_new dot k_j) / sqrt(d_k) for each cached key.
4. Compute numerically stable softmax weights:
   Compute attention weights: a_j = exp(s_j - max(s)) / sum(exp(s - max(s))).
5. Compute output vector o as the weighted sum of cached value vectors.
6. Return tuple (o, a) where o is list of floats (length d_v) and a is attention weights list.

      Implement the exact speculative decoding acceptance decision and residual distribution:
Write speculative_verify_token(token_draft, p_probs, q_probs, uniform_random_val):
Inputs:
- token_draft: Proposed token ID (int).
- p_probs: Target model probability distribution (list of floats summing to 1.0).
- q_probs: Draft model probability distribution (list of floats summing to 1.0).
- uniform_random_val: Random float value between 0.0 and 1.0 for acceptance decision.
      

      Requirements:
1. Compute acceptance probability: alpha = min(1.0, p(token_draft) / q(token_draft)).
2. If uniform_random_val < alpha:
   - Token is accepted. Return {"accepted": True, "token": token_draft, "residual_dist": None}.
3. If uniform_random_val >= alpha:
   - Token is rejected.
   - Compute residual distribution:
     Residual distribution: R(i) = max(0.0, p_i - q_i).
   - Normalize: R_norm(i) = R(i) / sum(R).
   - Return {"accepted": False, "token": None, "residual_dist": R_norm}.

        def test_speculative_always_accept():
    # If p(x) >= q(x), alpha = 1.0, always accept regardless of U
    p = [0.8, 0.2]
    q = [0.4, 0.6]
    # token 0: p=0.8, q=0.4 -> alpha = 1.0
    res = speculative_verify_token(0, p, q, uniform_random_val=0.99)
    assert res["accepted"] is True
    assert res["token"] == 0

def test_speculative_reject_residual():
    # token 1: p=0.2, q=0.6 -> alpha = 0.2 / 0.6 = 0.333
    p = [0.8, 0.2]
    q = [0.4, 0.6]
    res = speculative_verify_token(1, p, q, uniform_random_val=0.5) # 0.5 > 0.333 -> Reject
    assert res["accepted"] is False
    assert res["token"] is None
    # Residual: p - q -> max(0, 0.8 - 0.4) = 0.4; max(0, 0.2 - 0.6) = 0.0
    # Normalized residual must place 100% mass on token 0
    assert abs(res["residual_dist"][0] - 1.0) < 1e-5
    assert abs(res["residual_dist"][1] - 0.0) < 1e-5

def test_speculative_partial_accept():
    p = [0.5, 0.5]
    q = [0.8, 0.2]
    # token 0: alpha = 0.5 / 0.8 = 0.625
    res1 = speculative_verify_token(0, p, q, uniform_random_val=0.4)
    assert res1["accepted"] is True
    res2 = speculative_verify_token(0, p, q, uniform_random_val=0.7)
    assert res2["accepted"] is False

Inputs:
- logits: List of floats representing unnormalized token scores.
- generated_history: List of previously generated integer token IDs.
- penalty: Repetition penalty scalar (at least 1.0).
- allowed_mask: Optional list of booleans of vocabulary length; if allowed_mask[i] is False, token i is grammatically disallowed.
        

        Rules:
1. For each unique token ID in generated_history:
   - If logits[token] > 0: logits[token] = logits[token] / penalty
   - If logits[token] <= 0: logits[token] = logits[token] * penalty
2. If allowed_mask is provided:
   - For every token index i where allowed_mask[i] is False:
     set logits[i] = -10^9.
3. Return the modified logits list.

          def test_repetition_penalty():
    logits = [2.0, -2.0, 5.0]
    history = [0, 1]
    # token 0 is positive (2.0) -> 2.0 / 2.0 = 1.0
    # token 1 is negative (-2.0) -> -2.0 * 2.0 = -4.0
    # token 2 was not seen -> unchanged 5.0
    penalized = apply_penalties_and_grammar_mask(logits, history, penalty=2.0)
    assert abs(penalized[0] - 1.0) < 1e-6
    assert abs(penalized[1] - (-4.0)) < 1e-6
    assert abs(penalized[2] - 5.0) < 1e-6

def test_grammar_masking():
    logits = [10.0, 20.0, 30.0]
    mask = [True, False, True] # token 1 is disallowed by grammar
    masked = apply_penalties_and_grammar_mask(logits, [], allowed_mask=mask)
    assert masked[0] == 10.0
    assert masked[1] == -1e9
    assert masked[2] == 30.0

def test_both_applied():
    logits = [4.0, 4.0]
    history = [0]
    mask = [True, True]
    out = apply_penalties_and_grammar_mask(logits, history, penalty=2.0, allowed_mask=mask)
    assert abs(out[0] - 2.0) < 1e-6
    assert abs(out[1] - 4.0) < 1e-6

          

          Misconceptions
            

          • "Speculative decoding alters the output text distribution of the target model." Speculative decoding uses exact acceptance probabilities and residual resampling that mathematically guarantee the final output distribution is indistinguishable from running the target model directly.
            • 

          • "Decoding speed is limited by GPU TFLOPs computing power." Single-token decoding is heavily memory-bandwidth bound; the GPU spends over 90% of its time waiting to transfer model weights from VRAM to compute cores.
            • 

          • "Greedy decoding (temperature 0) always produces the most coherent and natural text." Greedy search frequently gets trapped in repetitive loops; sampling with moderate temperature and nucleus filtering consistently produces higher human-evaluated quality.
            • 

          • "KV caching decreases overall GPU VRAM usage." The KV cache eliminates redundant computation but consumes significant additional VRAM that scales linearly with batch size and sequence length.
            • 

          Where it breaks
          LLM inference breaks down when concurrent requests exceed available KV cache memory leading to out-of-memory crashes, when low-temperature sampling triggers pathological phrase repetition loops, or when speculative decoding draft models have low acceptance rates (e.g. <30%), causing validation overhead that makes generation slower than standard decoding.
          In your real work
          Production LLM serving engines such as vLLM, TensorRT-LLM and llama.cpp rely on paged KV caches, speculative decoding and grammar-constrained logit masking. On-device, grammar masking is what guarantees a structurally valid JSON response first time, because there is no server to re-ask when the output does not parse.
          Flash cards
          What is the difference between prefill and decode phases?
          Prefill processes prompt tokens in parallel (compute-bound); decode generates one token at a time sequentially (memory-bound).
          Why does single-batch LLM decoding underutilize GPU compute cores?
          Because loading gigabytes of model weights to perform a single token matrix-vector multiplication is bottlenecked by memory bandwidth.
          What does the KV cache store?
          Past Key and Value activation vectors across attention layers, preventing slow quadratic recomputation during autoregressive generation.
          How does speculative decoding achieve speedup without quality loss?
          A small draft model proposes multiple tokens cheaply, which the target model verifies in a single parallel step with exact acceptance-rejection criteria.
          What is nucleus (top-p) sampling?
          Sampling from the smallest set of high-probability tokens whose cumulative probability mass exceeds threshold p.
          How does repetition penalty discourage loops?
          By dividing positive logits (or multiplying negative logits) of previously generated tokens by a penalty scalar greater than 1.0.
