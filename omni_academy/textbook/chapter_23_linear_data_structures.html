1. The Crime Scene: The 45-Second Append Freeze

A junior engineer builds a high-frequency trading logger that appends incoming trade prices to an array.

Every time a price arrives, the code calls `realloc(buffer, size + 1)`.

For the first 1,000 items, the code is lightning fast. At 100,000 items, adding a single trade takes 20 milliseconds! At 1,000,000 items, the app freezes for 45 seconds!

Why? Because every append forces the operating system to find a new contiguous block of memory and copy all previous 999,999 items over!

By doubling capacity (1 -> 2 -> 4 -> 8 -> 16...), the total copies across 1,000,000 items is less than 2,000,000, reducing append time from O(N^2) to O(1) amortized!

💡 Real-World Metaphor: The Revolving Sushi Bar Conveyor

Imagine a revolving sushi bar with 8 seats arranged in a circle:
The chef places plates at the Head index; customers eat plates at the Tail index.
When the chef reaches seat 7, the next plate goes to seat 0!
Nobody ever has to rebuild the restaurant or move the conveyor belt. Memory is fixed, allocations are zero, and data flows smoothly in a continuous ring!

2. The Core Principle: Understanding the Mechanics

Dynamic array capacity doubling guarantees O(1) amortized insertion. Circular ring buffers provide lock-free FIFO streaming over fixed memory.

⚡ Permanent Mnemonic Anchor
The B.U.F.F.E.R. Ring
"Bitwise mask modulo for power-of-two rings · Uniform O(1) amortized push · Fast lock-free circular queue streaming · Fixed RAM footprint never triggers GC · Essential for high-fps audio and LLM token queues."
When buffer size is a power of two (e.g. 1024), index wrapping is computed with a single CPU instruction: next_index = (index + 1) & (SIZE - 1), avoiding slow division instructions.
