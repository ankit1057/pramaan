1. The Crime Scene: The Memory Leak That Drained 800 MB

A user navigates back and forth between the Home screen and the Profile screen in a Flutter app 20 times.

The app gets slower and slower until Android kills it with an OutOfMemoryError.

You inspect the memory heap: there are 20 invisible ProfileScreen instances still alive in RAM!

Why? The ProfileScreen registered a callback listener to the global UserSession event bus, but never cancelled the subscription when the widget was popped!

The global event bus held strong references to all 20 destroyed widgets, preventing the garbage collector from reclaiming a single byte!

💡 Real-World Metaphor: The Magazine Postal Tube

Think of a newspaper publisher:
The printing press doesn't know who you are; it simply drops newspapers into postal distribution tubes.
Subscribers receive papers as they roll off the press.
If you move to a new house, you unsubscribe so the mail carrier doesn't pile thousands of newspapers on your old doorstep until the porch collapses!

2. The Core Principle: Understanding the Mechanics

Decouples event publishers from subscribers via reactive event buses, supporting asynchronous state distribution without tight coupling.

⚡ Permanent Mnemonic Anchor
The R.E.A.C.T. Stream
"Register subscribers loosely without tight coupling · Emit immutable event payloads · Asynchronous stream dispatch buffers UI events · Cancel subscriptions on widget dispose to stop memory leaks · The heartbeat of Flutter Streams and Kotlin Flows."
Producers emit events; consumers react. Operators like debounce, map, and filter transform data pipelines without modifying producer source code.
