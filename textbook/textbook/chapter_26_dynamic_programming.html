1. What is Dynamic Programming? (The Notepad Story)

Imagine you write this on a piece of paper for a child: $$1 + 1 + 1 + 1 + 1$$ You ask: "What does this equal?"
The child counts their fingers: "Five!"
Now you write another $+ 1$ on the right side: $$1 + 1 + 1 + 1 + 1 + 1$$ You ask: "What does it equal now?"
Does the child start counting from the beginning: "One, two, three..."?
NO! Instantly, they say: "Six!"
You ask: "How did you know so fast?"
They say: "You just added one to the five we already had!"

🐘 The Elephant with a Notepad

Pure Recursion is a Goldfish: It has a 3-second memory. Every time it needs Fibonacci(5), it recalculates Fibonacci(4), Fibonacci(3), Fibonacci(2) from scratch over and over, taking exponential time $\mathcal{O}(2^N)$!

Dynamic Programming is an Elephant with a Notepad:
Whenever it solves a riddle, it writes the answer in its notepad (`dp[state] = answer`).
If anyone ever asks for that answer again, it glances at the notepad in $\mathcal{O}(1)$ time!

🧠 Permanent Memory Anchor #1
The F.A.S.T. Framework for DP
Find subproblems, Allocate table, Store answers, Trace back!
1. Find: What variables define my current situation? (e.g. item_index, remaining_capacity).
2. Allocate: Create an array or matrix dp[i][w] initialized to 0.
3. Store: Transition formula: $dp[i][w] = \max(\text{skip}, \text{take})$.
4. Trace: Walk backwards through the table to see which items were chosen!

2. The Smart Backpack (0/1 Knapsack)

You are an adventurer exploring an ancient temple. Your backpack can hold at most $W = 7\text{ kg}$.
You find 4 treasure artifacts on pedestals:
• Item 1: $(w_1 = 1\text{ kg}, v_1 = \$1)$
• Item 2: $(w_2 = 3\text{ kg}, v_2 = \$4)$
• Item 3: $(w_3 = 4\text{ kg}, v_3 = \$5)$
• Item 4: $(w_4 = 5\text{ kg}, v_4 = \$7)$

The Binary Decision at Every Pedestal:

For every item $i$, you face a choice:
• Choice A (Leave it): You don't take it. Your value is whatever the best pack was without it: $DP[i-1, w]$.
• Choice B (Take it): You take it (only if $w \ge w_i$). You gain its value $v_i$, and your remaining capacity shrinks to $w - w_i$. Your value is $DP[i-1, w - w_i] + v_i$.

$$DP[i, w] = \max\left(DP[i-1, w], \; DP[i-1, w - w_i] + v_i\right)$$
🧠 Permanent Memory Anchor #2
The Reverse-Loop Rule for 1D Knapsack
"Loop from Right to Left, or You'll Double-Count the Theft!"
When optimizing 2D memory into a single 1D array dp[w], you MUST loop $w$ backwards from $W$ down to $w_i$: 
for w in range(W, w_i - 1, -1):
    dp[w] = max(dp[w], dp[w - w_i] + v_i)
If you looped forward (left to right), dp[w - w_i] would already contain the new value from the current item, allowing you to steal the same item multiple times!
